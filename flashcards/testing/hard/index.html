Consumer-Driven Contract Testing (CDC)?

Quick Answer

A pattern for testing interactions between API providers and consumers in Microservices (e.g., using Pact).

Detailed Explanation

Instead of the Provider dictating the API, Consumers define a 'Contract' of what they need. The Provider validates they satisfy all contracts. This prevents breaking changes without spinning up full E2E environments.

Cyclomatic Complexity and testing?

Quick Answer

A code metric indicating the number of linearly independent paths through a program's source code.

Detailed Explanation

Formula: Edges - Nodes + 2. Higher complexity implies more branches (if/else), requiring more test cases to achieve full path coverage. It helps identify code that is hard to test and needs refactoring.

Explain 'Shift Left' testing.

Quick Answer

Moving testing activities earlier in the development lifecycle.

Detailed Explanation

Instead of waiting for 'QA Phase' after coding is done, testing starts during requirements (Acceptance Criteria), design (Architecture Review), and coding (TDD, Static Analysis). The cost of fixing a bug increases exponentially the later it is found.

How to test Distributed Systems (Chaos Engineering)?

Quick Answer

Intentionally injecting failures (network latency, pod crashes, packet loss) into a production-like system to verify resilience.

Detailed Explanation

Popularized by Netflix (Chaos Monkey). The goal is not just to break things, but to prove the system auto-heals without human intervention. Start small (delete one non-critical pod) before attacking critical paths.

Metamorphic Testing?

Quick Answer

A technique used when the 'correct' output is hard to know (oracle problem), by checking relations between inputs and outputs.

Detailed Explanation

Example: Testing a Search Engine. You don't know the exact search results for 'Cat'. But you know that 'Cat' results should be a subset of 'Cat OR Dog'. If checking specific values is impossible, check the properties of the change.

Property-Based Testing?

Quick Answer

Instead of specifying exact inputs (Example Testing), you define general properties that output should satisfy for a range of generated inputs.

Detailed Explanation

Example: 'For any list of integers, reverse(reverse(list)) should equal list'. The library (like QuickCheck or Hypothesis) generates hundreds of random lists, including edge cases, to try and falsify the property.

Snapshot Testing?

Quick Answer

Capturing the rendered output (e.g., UI component or JSON response) and comparing it to a stored 'golden' reference file.

Detailed Explanation

Popular in Jest/React. It detects unintended UI changes. Danger: Developers often mindlessly update snapshots when they fail, treating them as a nuisance rather than a regression warning.

Test Double vs Mock vs Fake?

Quick Answer

Test Double is the generic term. Fake has working implementation but is not suitable for prod (e.g., InMemoryDB). Mock verifies behavior.

Detailed Explanation

A Fake allows stateful testing (save user, then find user returns it). A Mock just cares about function calls. Use Fakes for integration-style checks in unit tests.

Testing Pyramid vs Testing Trophy?

Quick Answer

Pyramid emphasizes Unit Tests. Trophy (Kent C. Dodds) emphasizes Integration Tests.

Detailed Explanation

The Trophy argues that Integration tests give the most confidence per dollar. 'Write tests. Not too many. Mostly integration'. Unit tests mock too much; E2E are too slow. Integration hits the sweet spot.

What is Mutation Testing?

Quick Answer

A technique to evaluate the quality of your tests by deliberately modifying the application code (introducing 'mutants') and checking if tests fail.

Detailed Explanation

If you change a > b to a >= b in the code, and your test suite still passes, the mutant 'survived', meaning your tests have a blind spot. It tests the tests.
