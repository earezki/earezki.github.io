Code Coverage vs Test Coverage?

Quick Answer

Code Coverage is a metric (percentage) of lines/branches executed by tests. Test Coverage is a qualitative measure of how well the features/risks are tested.

Detailed Explanation

100% Code Coverage != 0 Bugs. You can hit every line but miss edge case logic (e.g., dividing by zero). High code coverage is necessary but not sufficient.

Mock vs Stub vs Spy?

Quick Answer

Stub: returns hardcoded data. Mock: verifies interactions (was this method called?). Spy: wraps real object to track calls while keeping real behavior.

Detailed Explanation
  • Stub: 'When getUser(1) is called, return {id:1}'.
  • Mock: 'Assert that sendEmail() was called exactly once'.
  • Spy: 'Call the real method, but tell me afterwards how many times it was called'.

Performance Testing types?

Quick Answer

Load Testing (Normal expected load), Stress Testing (Breaking point), Scalability Testing (Can it scale up?), Soak Testing (Long duration).

Detailed Explanation

Load testing verifies SLAs (e.g., 'API responds < 200ms at 1000 RPS'). Stress testing finds what happens when limit is exceeded (does it recover or corrupt data?).

Static Application Security Testing (SAST)?

Quick Answer

Testing the source code for security vulnerabilities without running the application (White Box).

Detailed Explanation

Tools (like SonarQube, Checkmarx) scan code for known patterns like SQL Injection possibilities, hardcoded passwords, or insecure crypto usage. It shifts security left.

What is BDD (Behavior-Driven Development)?

Quick Answer

An extension of TDD that focuses on system behavior described in plain English (Given-When-Then).

Detailed Explanation

It encourages collaboration between developers, QA, and business stakeholders. Tools like Cucumber or SpecFlow parse these 'Feature Files' (Given user is logged in, When they click buy, Then...) into executable tests.

What is Flaky Test?

Quick Answer

A test that produces different results (pass/fail) for the same code commitment.

Detailed Explanation

The worst enemy of CI. Causes: Network timing, async race conditions, dependency on shared state/randomness, or test order dependency. Flaky tests destroy trust in the test suite.

What is Fuzz Testing (Fuzzing)?

Quick Answer

A technique where you input massive amounts of random, invalid, or unexpected data into the system to make it crash.

Detailed Explanation

It helps find memory leaks, buffer overflows, and unhandled exceptions. If the app crashes on receiving %s%s, you found a bug.

What is Smoke Testing?

Quick Answer

A preliminary set of tests run on a new build to decide if it is stable enough for deeper testing.

Detailed Explanation

Also known as 'Build Verification Testing'. If the login page is 404 or the app crashes on startup, the smoke test fails, and testers don't waste time on detailed regression testing.

What is TDD (Test-Driven Development)?

Quick Answer

A development process where you write the test before the code. Cycle: Red (Write failing test) -> Green (Write minimal code to pass) -> Refactor.

Detailed Explanation

TDD forces you to design your API from the user's perspective (the test) and results in high test coverage and modular code. It prevents 'writing tests that just pass the code you already wrote'.

What is the Test Pyramid?

Quick Answer

A conceptual framework suggesting you should have many Unit Tests, fewer Integration Tests, and very few E2E Tests.

Detailed Explanation

Unit tests are cheap and fast. E2E tests are expensive, slow, and flaky. An 'Ice Cream Cone' antipattern happens when you have mostly manual/E2E tests and few unit tests, leading to long feedback loops.
