ShardingKey

Choosing a good Shard Key?

Quick Answer

High cardinality + High write randomness.

Detailed Explanation

Bad keys: Monotonically increasing (autoincrement ID) -> All writes go to one shard (Hotspot). Low cardinality (Status) -> Unbalanced chunks (Jumbo Chunks).

Read Concern vs Write Concern?

Quick Answer

Write Concern: How many nodes must confirm write (w:1, w:majority). Read Concern: How fresh/durable needs the read data be (local, majority, linearizable).

Detailed Explanation

readConcern: majority guarantees data returned has been written to a majority of replicas and won't be rolled back.

Sharding in MongoDB?

Quick Answer

Detailed Explanation

Uses a Shard Key to partition data into Chunks. Balancer migrates chunks between shards to ensure even load. Essential for horizontal scaling beyond single-server limits.

Quick Answer
