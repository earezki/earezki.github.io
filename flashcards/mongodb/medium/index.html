$elemMatch operator?

Quick Answer

Matches documents containing an array field with at least one element that matches all specified criteria.

Detailed Explanation

Without $elemMatch, criteria { 'scores.min': { $gt: 5 }, 'scores.max': { $lt: 10 } } could match different elements in the array. $elemMatch ensures they apply to the same element.

Code Example

find({ scores: { $elemMatch: { $gt: 80, $lt: 90 } } })

$group stage?

Quick Answer

Group by key.

Detailed Explanation

Groups input documents by the specified _id expression and outputs a document for each distinct grouping.

Code Example
{ $group: { _id: "$cust_id", total: { $sum: "$amount" } } }

$lookup operator?

Quick Answer

Performs a Left Outer Join to another collection.

Detailed Explanation

Brings in data from "joined" collection as an array field in the document. Expensive operation in distributed systems.

Code Example

{ $lookup: { from: 'inventory', localField: 'item', foreignField: 'sku', as: 'inv_docs' } }

Capped Collections?

Quick Answer

Fixed-size collections that support high-throughput insert/retrieve operations based on insertion order.

ModelingSchema

Data Modeling: Embedding vs Referencing?

Quick Answer

Embedding (Nested Docs): Data likely accessed together, one-to-few. Referencing (Normalization): Data accessed independently, one-to-many/many-to-many.

Detailed Explanation

Embedding improves read performance (1 query). Referencing avoids data duplication but requires application-level joins or $lookup.

Embedded vs Referenced relationships?

Quick Answer

Nested vs Foreign Key.

Detailed Explanation
  • Embedded: Storing related data in a single document. Good for 1-to-few, read performance.
  • Referenced: Storing link (ObjectId) to another document. Good for 1-to-many, non-repetition.
