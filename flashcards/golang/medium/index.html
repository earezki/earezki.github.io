Quick Answer

Detailed Explanation

From Go 1.5+, it defaults to the number of CPU cores. Adjusting it can tune performance for CPU-bound vs I/O-bound workloads, but usually best left default.

panic and recover?

Quick Answer

panic stops normal execution (like throwing exception). recover regains control of a panicking goroutine.

Detailed Explanation

recover is only useful inside a deferred function. If not recovered, the program crashes with a stack trace. Generally, you should return error instead of panicking.

Code Example

defer func() {
if r := recover(); r != nil {
fmt.Println("Recovered", r)
}
}()
panic("error")

select statement?

Quick Answer

Wait on multiple channels.

Detailed Explanation

Like switch, but for channels. Blocks until one case can proceed. If multiple are ready, chooses randomly.

Code Example

select statement?

Quick Answer

The select statement lets a goroutine wait on multiple communication operations (channels).

Detailed Explanation

It blocks until one of its cases can run. If multiple can run, it chooses one at random. It is essentially a switch for channels. A default case makes it non-blocking.

Code Example

select {
case msg1 := <-c1:
fmt.Println(msg1)
case <-time.After(time.Second):
fmt.Println("timeout")
}

concurrency

Buffered vs Unbuffered Channels?

Quick Answer

Async vs Sync.

Detailed Explanation
  • Unbuffered: Blocks sender until receiver is ready (Synchronous).
  • Buffered: Blocks sender only when buffer is full (Asynchronous up to limit).
Code Example
ch := make(chan int) // Unbuffered
ch := make(chan int, 10) // Buffered

Buffered vs Unbuffered Channels?

Quick Answer

Unbuffered channels block the sender until the receiver reads. Buffered channels block only when the buffer is full.

Detailed Explanation

Unbuffered channels provide strong synchronization. Buffered channels decouple the producer and consumer speed, useful for handling bursts of tasks or avoiding deadlocks in specific patterns.

Code Example

ch := make(chan int, 3) // Buffer size 3
ch <- 1 // Non-blocking

collections

Map concurrency safety?

Quick Answer

Not safe.

Detailed Explanation

Maps are not safe for concurrent read/write. Results in runtime panic. Use sync.Map or Mutex.

Code Example
fatal error: concurrent map writes

Map mechanics in Go?

Quick Answer

Maps are hash tables. They are unordered. Reading from a nil map returns zero value, writing to a nil map panics.

Detailed Explanation

Maps are reference types. When you pass a map to a function, modifications are visible to the caller. They are not thread-safe; use sync.RWMutex or sync.Map for concurrent access.

Code Example

m := make(map[string]int)
m["k"] = 1
delete(m, "k")

Method Receivers: Point vs Value?

Quick Answer

Mutation requirement.

Detailed Explanation
  • Pointer Recv (*T): Can modify object. Avoids copying (efficiency).
  • Value Recv (T): Cannot modify. Safe copy.
Code Example
func (p *Point) Move() { ... }

Method Receivers: Value vs Pointer?

Quick Answer

Use Pointer Receiver (p *Type) if you need to modify the struct or if the struct is large (copying is expensive). Use Value Receiver (p Type) for immutability or small types.

Detailed Explanation

If a method modifies the receiver, you MUST use a pointer. If you use a value receiver, the method works on a copy, and changes are lost after return.

Code Example

func (p *Person) SetName(n string) {
p.Name = n // Modifies original
}

Slice Cap vs Len?

Quick Answer

Capacity vs Length.

Detailed Explanation
  • Len: Number of elements in slice.
  • Cap: Size of underlying array (from start index).
Code Example
len(s) <= cap(s)

Slice Tricks: Growing and Appending?

Quick Answer

append adds elements to a slice. If the underlying array is full, it allocates a larger array (usually double size) and copies elements.

Detailed Explanation

Because re-allocation is expensive, if you know the size upfront, use make([]T, 0, capacity) to reserve memory and avoid overhead.

Code Example

s := []int{1}
s = append(s, 2, 3)

What are Interfaces in Go?

Quick Answer

Interfaces are set of method signatures. A type implements an interface implicitly if it implements all the methods.

Detailed Explanation

There is no implements keyword. This 'Structural Typing' (Duck Typing) allows for decoupling and flexibility. The empty interface interface{} can hold values of any type.

Code Example

}

What is context package used for?

Quick Answer

To carry deadlines, cancellation signals, and request-scoped values across API boundaries and between processes (goroutines).

Detailed Explanation

It is critical for preventing goroutine leaks. If a request is cancelled (e.g., HTTP timeout), the Context is cancelled, and all child goroutines spawned with that context should stop work.

Code Example

ctx, cancel := context.WithTimeout(parent, 10*time.Second)
defer cancel()
