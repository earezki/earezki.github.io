ServerlessDynamoDB

DynamoDB Write Sharding?

Quick Answer

Technique to distribute writes across partitions when a single Partition Key becomes hot (e.g., 'Election Day' events).

Detailed Explanation

Suffix key with random number 1..N. PK=Candidate A#3. Read all partitions (Query 1..N) and aggregate. Solves 'Hot Partition' throttling.

Quick Answer

Uses generic PK/SK names (PK, SK). Example: User is PK=USER#1, SK=INFO. User's Orders are PK=USER#1, SK=ORDER#100. Fetch both with one query (Query PK=USER#1). Requires careful planning.

database

What causes a Hot Partition in DynamoDB?

Quick Answer

Poor Partition Key design.

Detailed Explanation

If access is unevenly distributed (e.g., everyone accessing Key 'A'), one partition is overwhelmed while others are idle. Good keys have high cardinality and random access.

Code Example
Avoid monotonic keys (timestamps).
