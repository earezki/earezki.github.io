ALB vs NLB?

Quick Answer

Application Load Balancer (L7) vs Network Load Balancer (L4).

Detailed Explanation

Application Load Balancer (ALB) operates at Layer 7, inspecting HTTP/HTTPS traffic for content-based routing, while Network Load Balancer (NLB) works at Layer 4, handling TCP/UDP with ultra-low latency. Core functionality: ALB supports path-based, host-based routing, SSL termination; NLB for high-performance, static IP. Internal mechanics: ALB uses rules and target groups; NLB uses listeners and targets. Recommended practices: Use ALB for web apps needing routing, NLB for gaming or IoT. Common mistakes: Choosing ALB for non-HTTP traffic, or NLB when content inspection needed. Use cases: Web apps (ALB), real-time gaming (NLB). Performance: NLB handles millions of requests/sec; cost: ALB slightly higher due to features.

Code Example

Lambda Authorizer function

def lambda_handler(event, context):
token = event.get('authorizationToken')
method_arn = event['methodArn']

if not token:
    raise Exception('Unauthorized')

# Validate token (e.g., JWT)
try:
    # Decode and verify JWT
    payload = jwt.decode(token, 'secret', algorithms=['HS256'])
    principal_id = payload['user_id']
    
    # Generate policy
    policy = {
        'principalId': principal_id,
        'policyDocument': {
            'Version': '2012-10-17',
            'Statement': [
                {
                    'Action': 'execute-api:Invoke',
                    'Effect': 'Allow',
                    'Resource': method_arn
                }
            ]
        }
    }
    return policy
except jwt.ExpiredSignatureError:
    raise Exception('Token expired')
except jwt.InvalidTokenError:
    raise Exception('Invalid token')

Code Example
import boto3
from botocore.exceptions import ClientError

# Boto3 example to create an Auto Scaling Group
client = boto3.client('autoscaling', region_name='us-east-1')

try:
    response = client.create_auto_scaling_group(
        AutoScalingGroupName='my-asg',
        LaunchTemplate={
            'LaunchTemplateName': 'my-template',
            'Version': '$Latest'
        },
        MinSize=1,
        MaxSize=10,
        DesiredCapacity=2,

        AutoScalingGroupName='my-asg',
        PolicyName='cpu-scaling',
        PolicyType='TargetTrackingScaling',
        TargetTrackingConfiguration={
            'PredefinedMetricSpecification': {
                'PredefinedMetricType': 'ASGAverageCPUUtilization'
            },
            'TargetValue': 70.0
        }
    )

Cost implications: pay for data transfer out and requests; edge locations in premium regions cost more.

DynamoDB Partition Key vs Sort Key?

Quick Answer

Partition Key determines which node stores data (hashes). Sort Key sorts data within partitions.

Detailed Explanation

In DynamoDB, the partition key is a primary key attribute that determines the physical storage location of items by hashing the key to distribute data across partitions. The sort key (optional) allows for composite primary keys, enabling efficient range queries and sorting within each partition. Core functionality includes supporting hierarchical data models like user orders (PK: User#ID, SK: Order#Timestamp). Internal mechanics involve consistent hashing for partition distribution and B-tree structures for sort key ordering. Recommended practices: Choose partition keys with high cardinality to avoid hot partitions; use sort keys for time-series or lexicographical ordering. Common mistakes: Using low-cardinality partition keys leading to throttling; forgetting sort keys for complex queries. Practical use cases: E-commerce order history, IoT sensor data, user profiles with multiple attributes. Performance implications: Partition keys affect read/write capacity distribution; sort keys enable efficient pagination. Cost implications: Uneven partitions can increase WCU/RCU costs due to hotspots.

Code Example

import boto3
from boto3.dynamodb.conditions import Key

dynamodb = boto3.resource('dynamodb')
table = dynamodb.Table('UserOrders')

Query with partition key only

def get_user_orders(user_id):
try:
response = table.query(
KeyConditionExpression=Key('PK').eq(f'User#{user_id}')
)
return response['Items']
except Exception as e:
print(f'Error querying: {e}')
return []

Query with composite key (partition + sort)

def get_user_orders_after_date(user_id, start_date):
try:
response = table.query(
KeyConditionExpression=Key('PK').eq(f'User#{user_id}') & Key('SK').begins_with(f'Order#{start_date}')
)
return response['Items']
except Exception as e:
print(f'Error querying: {e}')
return []

Example usage

print(orders)

orders_after = get_user_orders_after_date('123', '2023-01-01')

Code Example
import boto3
from botocore.exceptions import ClientError

ec2 = boto3.client('ec2', region_name='us-east-1')

def create_subnet(vpc_id, cidr, availability_zone, public=False):
    try:
        response = ec2.create_subnet(
            VpcId=vpc_id,
            CidrBlock=cidr,
            AvailabilityZone=availability_zone
        )

            )
        return subnet_id
    except ClientError as e:

What is KMS?

Quick Answer

Key Management Service.

Detailed Explanation

KMS creates and manages encryption keys for AWS services. Core functionality: Symmetric/asymmetric keys, rotation. Internal mechanics: Hardware security modules. Recommended practices: Rotate keys annually. Common mistakes: Not using key aliases. Use cases: S3 encryption, RDS. Performance: Throttling limits. Cost implications: Per key + API calls.

Code Example
import boto3
from botocore.exceptions import ClientError

# Boto3 example for KMS encryption
kms = boto3.client('kms', region_name='us-east-1')

try:
    # Create key
    key_response = kms.create_key(
        Description='My encryption key',
        KeyUsage='ENCRYPT_DECRYPT'
    )
    key_id = key_response['KeyMetadata']['KeyId']
    
    # Encrypt data
    plaintext = b'Hello, World!'
    encrypt_response = kms.encrypt(
        KeyId=key_id,
        Plaintext=plaintext
    )
    ciphertext = encrypt_response['CiphertextBlob']
    
    # Decrypt data
    decrypt_response = kms.decrypt(
        CiphertextBlob=ciphertext
    )
    decrypted = decrypt_response['Plaintext']
    
    print(f"Original: {plaintext}")
    print(f"Decrypted: {decrypted}")
    
except ClientError as e:
    print(f"KMS error: {e}")
