directives

@deprecated?

Quick Answer

Mark field obsolete.

Detailed Explanation

Built-in directive to mark a field or enum value as deprecated with a reason.

Code Example
@deprecated(reason: "Use newField")
directives

@include?

Quick Answer

Conditional field.

Detailed Explanation

Built-in directive. Only includes this field in the result if the argument is true.

Code Example
field @include(if: $foo)
directives

@skip?

Quick Answer

Conditional exclude.

Detailed Explanation

Opposite of @include. Skips the field if the argument is true.

Code Example
field @skip(if: $foo)
errors

errors field?

Quick Answer

Partial failure.

Detailed Explanation

GraphQL can return both data (partial) and errors (array) if something went wrong but not fatally.

Code Example
{ data: ..., errors: [...] }
resolvers

root / parent?

Quick Answer

Previous object.

Detailed Explanation

First argument of resolver. Object returned by the parent resolver.

Code Example
(parent) => parent.id
resolvers

Async Resolvers?

Quick Answer

Wait for Promise.

Detailed Explanation

Resolvers can return Promises. GraphQL engine waits for them to resolve before building response.

Code Example
async () => db.find(...)

Connection Type?

Quick Answer

Relay standard.

Detailed Explanation

Wrapper type around a list to provide pagination metadata (edges, nodes, pageInfo).

Code Example

resolvers

Context?

Quick Answer

Global state per req.

Detailed Explanation

Third argument passed to every resolver. Used to pass auth tokens, database connections, or dataloaders.

Code Example
context.userId
pagination

Cursor Pagination?

Quick Answer

Edges and Nodes.

Detailed Explanation

Standard (Relay) way to paginate. Uses a pointer (cursor) to identify items, instead of offset.

Code Example
type PageInfo { endCursor ... }

Fragments?

Quick Answer

Reusable units.

Detailed Explanation

Allow constructing sets of fields, and then including them in queries where you need to.

query

Inline Fragment?

Quick Answer

Type check.

Detailed Explanation

Used to access fields on a specific Type when querying an Interface or Union.

Code Example
... on Droid { primaryFunction }
types

Interface?

Quick Answer

Abstract type.

Detailed Explanation

Abstract type that includes a certain set of fields that a type must include to implement the interface.

Code Example
interface Character { name: String! }
mutations

Mutation Payload?

Quick Answer

Best Practice.

Detailed Explanation

Wrapping mutation return type in a specific object (e.g. UpdateUserPayload) to allow returning metadata/errors.

Code Example
type UpdateUserPayload { user, errors }

Non-Null List?

Quick Answer

List itself is not null, AND items inside are not null.

Code Example
[String!]!

Custom logic.

Union?

Quick Answer

One of many.

Detailed Explanation

Type usually used for return values that can be one of several different Object types (no shared fields required).

Code Example
