@Bean vs @Component?

Quick Answer

@Component is for class-level scanning; @Bean is for method-level definition in @Configuration.

Detailed Explanation

Use @Component for your own classes. Use @Bean when you need to configure a 3rd party class where you can't add annotations to the source code.

Code Example
@Bean
public RestTemplate restTemplate() { return new RestTemplate(); }

Difference between properties and YAML in Spring Boot?

Quick Answer

Are mostly equivalent, but YAML supports hierarchical arrays and maps more naturally.

Detailed Explanation

Properties files (key=value) are flat and can get repetitive (spring.datasource.url=..., spring.datasource.username=...). YAML allows nested structure, which is more readable. However, using @PropertySource annotation only supports .properties files by default, not YAML.

How does @Transactional work?

Quick Answer

It wraps the method execution in a database transaction context.

Detailed Explanation

It uses AOP proxies. When the method starts, a transaction is begun. If the method finishes successfully, the transaction is committed. If an unchecked exception (RuntimeException) is thrown, the transaction is rolled back. Checked exceptions do NOT trigger rollback by default unless configured.

Code Example

@Transactional
public void transferMoney() { ... }

How to handle exceptions globally in Spring Boot?

Quick Answer

Using @ControllerAdvice (or @RestControllerAdvice) class and @ExceptionHandler methods.

Detailed Explanation

This pattern allows you to define a single class that intercepts exceptions thrown by any controller across the application. You can then return a standardized JSON error response structure (e.g., timestamp, status, error message) instead of raw stack traces.

Code Example

@RestControllerAdvice
public class GlobalExceptionHandler {
@ExceptionHandler(UserNotFoundException.class)
public ResponseEntity handle(Exception e) {
return ResponseEntity.status(404).body(e.getMessage());
}
}

SecurityJWT

Implement a JWT Authentication Filter.

Quick Answer

Intercepts requests, extracts 'Authorization: Bearer' token, validates it, and sets the SecurityContext.

Detailed Explanation

It usually extends OncePerRequestFilter. If valid, we create a UsernamePasswordAuthenticationToken and set it in SecurityContextHolder.

Code Example

protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain) {
String token = resolveToken(req);
if (token != null && jwtProvider.validateToken(token)) {
Authentication auth = jwtProvider.getAuthentication(token);
SecurityContextHolder.getContext().setAuthentication(auth);
}
chain.doFilter(req, res);
}

What is dependency injection (DI) in Spring?

Quick Answer

DI is a design pattern where the objects that a class needs (dependencies) are passed to it ('injected') rather than the class creating them itself.

Detailed Explanation

This achieves loose coupling. The Spring Container (IoC Container) manages the lifecycle of objects (Beans). You can inspect via Constructor Injection (recommended), Setter Injection, or Field Injection (@Autowired).

Code Example

class UserService {
private final UserRepository repo;

public UserService(UserRepository repo) { // Constructor Injection
    this.repo = repo;
}

What is Scoping in Spring Beans (Singleton vs Prototype)?

Quick Answer

The default scope is Singleton (one instance per container). Prototype creates a new instance every time it is requested.

Detailed Explanation

Other web-aware scopes exist: Request (one per HTTP request), Session (one per user session), and Application. Be careful injecting a Prototype bean into a Singleton bean; the prototype is only created once (at injection time), effectively behaving like a singleton.

Code Example

@Scope("prototype")
@Component
class MyBean { ... }

What is the difference between a Filter and an Interceptor?

Quick Answer

Filters belong to the Servlet container; Interceptors belong to the Spring context.

Detailed Explanation

Filters (Servlet API) intercept requests before they reach the DispatcherServlet. Interceptors (Spring MVC) intercept requests between the DispatcherServlet and the Controller. Interceptors have access to the handler and modelandview.

Code Example

// Interceptor: checking user session or logging
