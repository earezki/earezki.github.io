Rc<T> vs Arc<T>?

Quick Answer

Rc (Reference Counting) enables multiple ownership in single-threaded contexts. Arc (Atomic RC) does the same for multi-threaded contexts.

Detailed Explanation

Because Arc uses atomic primitives, it has a performance overhead. Use Rc if you don't need thread safety. Both are immutable; combine with RefCell or Mutex for mutability.

RefCell<T> and Interior Mutability?

Quick Answer

RefCell enforces borrowing rules at runtime instead of compile time.

Detailed Explanation

It allows 'mutating data even when there are immutable references to that data' (Interior Mutability). If you break the rules (two mutable borrows), it panics at runtime.

Explain unwrap() vs ? operator.

Quick Answer

unwrap() panics if the Result is Err. ? propagates the error to the calling function.

Detailed Explanation

unwrap is for prototyping. ? is for production error handling, allowing the error to bubble up to a place where it can be handled properly.

Code Example

let f = File::open("f.txt")?; // returns Err early if fails

Traits vs Interfaces?

Quick Answer

Traits are similar to interfaces: they define shared behavior. A type implements a trait.

Detailed Explanation

Unique to Rust: you can implement a Trait for a Type even if you don't own the type (as long as you own the Trait), known as the Orphan Rule. Traits can also have default method implementations.

Code Example

}

What are Lifetimes in Rust?

Quick Answer

Lifetimes ensure that references are valid as long as we use them. They prevent dangling pointers.

Detailed Explanation

Most lifetimes are inferred. Explicit annotation ('a) is needed when a function returns a reference and the compiler cannot distinguish which input reference it corresponds to.

Code Example

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
if x.len() > y.len() { x } else { y }
}
