'static lifetime?

Quick Answer

Lives forever.

Detailed Explanation

Reference valid for the entire duration of the program (e.g. string literals). Or a type that contains no non-static references.

Code Example
let s: &'static str = "hello";

async/await and Futures in Rust?

Quick Answer

Rust's async model is zero-cost. async functions return a Future, which does nothing until polled.

Detailed Explanation

Unlike JS node (builtin runtime), Rust needs an external Executor (like Tokio or async-std) to poll the futures. The state machine is generated at compile time.

interior-mutability

Cell vs RefCell?

Quick Answer

Interior Mutability.

Detailed Explanation
  • Cell<T>: Mutations via moving values in/out (Copy types).
  • RefCell<T>: Mutations via runtime borrow checking (borrow_mut()). Panics at runtime if rules violated.
Code Example
let c = RefCell::new(5);
*c.borrow_mut() += 1;

Cow (Clone on Write)?

Quick Answer

An enum that holds either a borrowed reference or an owned value.

Detailed Explanation

It allows specialized optimization: you can return a reference to existing data (cheap) most of the time, and only clone (alloc) if you actually need to modify it.

Code Example

use std::borrow::Cow;

Drop trait and destructor?

Quick Answer

The Drop trait allows you to customize what happens when a value goes out of scope.

Detailed Explanation

You implement the drop method. It is often used to release resources like files, sockets, or FFI locks. You cannot call drop(x) explicitly; use std::mem::drop(x) to force early drop.

Code Example

impl Drop for Custom {
fn drop(&mut self) { println!("Dropping!"); }
}

Rc<T> vs Arc<T>?

Quick Answer

Single vs Multi-threaded ref count.

Detailed Explanation
  • Rc: Reference Counted. Shared ownership on single thread.

Code Example

Send vs Sync traits?

Quick Answer

Send: ownership of the type can be transferred to another thread. Sync: safe to access via shared reference from multiple threads.

Detailed Explanation

Usually T is Sync if &T is Send. These are 'Marker Traits' (no methods) automatically implemented by the compiler. Rc is neither Send nor Sync. Mutex makes things Sync.

Dynamic Dispatch (dyn Trait).

Quick Answer

Dynamic dispatch happens when you use a Trait Object (Box<dyn Animal>). The compiler doesn't know the concrete type at compile time.

Detailed Explanation

It uses a vtable (virtual method table) to look up the method at runtime. This incurs a slight runtime penalty but allows for heterogeneous collections (a list of different Animals).

Code Example

let animals: Vec<Box> = vec![];

Explain Copy vs Clone traits.

Quick Answer

Clone explicitly duplicates an object (deep or shallow). Copy works implicitly via memory copy (memcpy) for types that fit on stack.

Detailed Explanation

Types like integers are Copy. If you assign let a = b; and b is Copy, b remains valid. If b is only Clone (like String), ownership moves, and b is invalid unless you call b.clone().

Pinning (Pin<P>)?

Quick Answer

Pin prevents a value from moving in memory. It is critical for self-referential structs generated by async/await futures.

Detailed Explanation

If a Future sits on the stack and points to its own internal buffer, moving it would break that pointer. Pinning asserts that the object stays at that memory address until dropped.

What are 'unsafe' blocks?

Quick Answer

unsafe allows you to bypass Rust's safety checks: dereference raw pointers, call unsafe functions (C FFI), or mutate statics.

Detailed Explanation

It doesn't disable the borrower checker. It effectively says 'I promise I checked the invariants here manually'. It is necessary for low-level systems programming (OS kernels) but should be minimized.

Code Example

unsafe {
let r = *raw_pointer;
}
