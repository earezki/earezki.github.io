Differences between 'Macvlan' and 'Ipvlan' network drivers?

Quick Answer

Macvlan assigns a unique MAC address to each container (appearing as a physical device), while Ipvlan shares the host MAC but uses distinct IPs.

Detailed Explanation

Macvlan is useful for legacy apps expecting a physical network interface presence, but can degrade performance on switches with MAC limits. Ipvlan is lighter on the network hardware (one MAC) but somewhat more complex to troubleshoot at L2.

Explain 'Rootless Docker'.

Quick Answer

Rootless mode allows running the Docker daemon and containers as a non-root user to mitigate potential security vulnerabilities.

Detailed Explanation

Traditionally, the Docker daemon runs as root. If compromised, it gives root access to the host. Rootless mode uses user namespaces to map the container's root user to a regular user on the host, ensuring that even a container breakout doesn't lead to host root access.

How do Multi-Architecture Images (Manifest Lists) work?

Quick Answer

They allow a single image tag (like node:14) to support multiple architectures (amd64, arm64) by pointing to a manifest list that references architecture-specific images.

Detailed Explanation

When you pull an image, the Docker client checks the manifest list and automatically pulls the variant matching your host's architecture. This is crucial for supporting both x86 servers and ARM-based devices (like Apple Silicon or Raspberry Pi) seamlessly.

How does Docker use Linux Namespaces?

Quick Answer

Namespaces provide the process isolation that creates the illusion of a separate container. Docker uses several, including PID (process), NET (networking), MNT (filesystem), and UTS (hostname).

Detailed Explanation

When you start a container, Docker creates a set of namespaces for it. The Process ID (PID) namespace ensures the container sees only its own processes. The Network namespace gives it its own network stack (IP, ports). This isolation is kernel-level and lightweight compared to VMs.

What are Cgroups (Control Groups) in Docker?

Quick Answer

Cgroups allow you to limit, account for, and isolate the physical resources (CPU, Memory, Disk I/O) used by a collection of processes (containers).

Detailed Explanation

While Namespaces isolate visibility, Cgroups isolate resource usage. Without cgroups, a single container could exhaust all host memory or CPU. Docker uses cgroups to enforce limits like --memory=512m or --cpus=1.0.

Code Example

docker run -it --cpus=".5" --memory="256m" ubuntu bash

Quick Answer

A method to reduce image size by using multiple FROM instructions.

You can compile binaries in a 'builder' stage filled with tools, and then COPY only the resulting binary to a lean runtime stage (like Alpine), discarding the heavy build tools.

What is the 'Zombie Process' problem in containers, and how is it solved?

Quick Answer

If the main process (PID 1) in a container doesn't handle child process reaping, 'zombie' processes accumulate, leaking resources. Using an init process solution like tini solves this.

Detailed Explanation

In Linux, PID 1 is responsible for reaping orphaned child processes. Many application binaries don't do this. Docker can run with --init (which uses tini), acting as a lightweight init system to properly reap zombies and forward signals.

Code Example

docker run --init my-app

What is the OverlayFS filesystem?

Quick Answer

OverlayFS is a Union Mount filesystem used by Docker to modify the filesystem while keeping the base image read-only.

Detailed Explanation

It layers a writable 'upper' directory over a read-only 'lower' directory (the image layers). When a process reads a file, it checks the upper then lower. When it writes, it performs a 'copy-up' to the upper layer. This efficiency is key to Docker's speed and storage management.
