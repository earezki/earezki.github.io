Explain Multi-stage Builds.

Quick Answer

Multi-stage builds allow you to use multiple FROM instructions in a single Dockerfile to separate the build environment from the runtime environment.

Detailed Explanation

This significantly reduces final image size. You can compile your application in a 'build' stage with all SDKs and tools, and then COPY only the compiled binary to a lean 'runtime' stage (like Alpine), discarding the heavy build tools.

Code Example

Build Stage

FROM golang:1.16 AS build
WORKDIR /app
COPY . .
RUN go build -o myapp

Run Stage

FROM alpine:latest
COPY --from=build /app/myapp .
CMD ["./myapp"]

Explain the depends_on option in Docker Compose.

Quick Answer

depends_on controls the startup and shutdown order of services.

Detailed Explanation

If Service A depends on Service B, Compose starts B before A. However, it only waits for B to start, not necessarily to be ready (e.g., database accepting connections). For readiness checks, you often need healthchecks or wait-for scripts.

Code Example

services:
web:
depends_on:
- db
db:
image: postgres

How can you reduce Docker Image Size?

Quick Answer

Use smaller base images (Alpine), multi-stage builds, minimize layers, and clean up cache/dependencies in the same RUN instruction.

Detailed Explanation

Chaining commands with && reduces the number of intermediate layers. Removing cache (like apt-get clean) prevents saving useless temporary files in the layer. Choosing alpine variants often saves hundreds of MBs.

Code Example

RUN apt-get update && apt-get install -y python3 \
&& rm -rf /var/lib/apt/lists/*

How do Docker Networks work (Bridge vs Host)?

Quick Answer

bridge is the default private network where containers communicate via IP/names. host removes network isolation, sharing the host's networking namespace.

Detailed Explanation

In bridge mode, containers get their own IP and port mapping is required. In host mode, the container shares the host's IP address directly; port 80 in the container binds to port 80 on the host. host is faster but offers less isolation.

Code Example

docker run --network host my-app

What are Dangling Images?

Quick Answer

Dangling images are layers that have no relationship to any tagged images, often shown as <none>:<none>.

Detailed Explanation

They are usually created during rebuilds when a new image takes the tag of an old one, leaving the old layers 'dangling'. They consume disk space and can be cleaned up using docker image prune.

What are Docker Restart Policies?

Quick Answer

Restart policies determine how Docker should handle a container that exits or fails. Common options are no, on-failure, always, and unless-stopped.

Detailed Explanation

always will restart the container indefinitely if it stops (even after reboot). on-failure only restarts if the container exits with a non-zero exit code. This is crucial for production reliability.

Code Example

docker run -d --restart always my-app

What is ENTRYPOINT vs CMD in a Dockerfile?

Quick Answer

ENTRYPOINT defines the executable to run, while CMD specifies default arguments for the entrypoint or the command itself if no entrypoint is set.

Detailed Explanation

ENTRYPOINT is meant to treat the container as an executable; commands pass arguments to it. CMD provides defaults that can be easily overridden by the user when running the container. Often they are used together: ENTRYPOINT sets the binary, CMD sets the default flags.

Code Example

ENTRYPOINT ["/bin/ping"]
CMD ["localhost"]

docker run my-image -> ping localhost

docker run my-image google.com -> ping google.com

What is a Bind Mount vs a Volume?

Quick Answer

A Volume is managed by Docker in a specific location, while a Bind Mount maps any directory on the host machine to the container.

Detailed Explanation

Bind mounts are dependent on the host's directory structure (e.g., /home/user/project), making them less portable but great for development (live code updates). Volumes are fully managed by Docker and are the correct choice for production data persistence.
