concatMap vs exhaustMap?

Quick Answer

concatMap queues requests; exhaustMap ignores new requests while busy.

Detailed Explanation
  • concatMap: Preserves order. Waits for inner observable to complete before starting next.
  • exhaustMap: If an inner observable is running, new source emissions are ignored (good for login buttons to prevent spamming).
Code Example
clicks.pipe(exhaustMap(() => login()))

scan vs reduce?

Quick Answer

Detailed Explanation
  • reduce: Emits only when stream completes (like Array.reduce).

switchMap vs mergeMap?

Quick Answer

switchMap cancels the previous inner observable; mergeMap runs them concurrently.

Detailed Explanation
  • switchMap: Good for search type-aheads (cancels old requests).
  • mergeMap: Good for not losing any requests (saves everything).
  • concatMap: Runs requests in order, waiting for previous to finish.
Code Example
searchBox.valueChanges.pipe(
  switchMap(term => this.searchService.search(term))
).subscribe();

AOT (Ahead-of-Time) vs JIT (Just-in-Time) compilation?

Quick Answer

JIT compiles templates in the browser (runtime). AOT compiles templates during the build process (server).

Detailed Explanation

AOT catches template errors at build time, reduces bundle size (the compiler itself isn't shipped), and renders faster (no compilation step on load). AOT is default in modern Angular.

What is ChangeDetectionStrategy.OnPush?

Quick Answer

A strategy that checks for changes only when input properties change.

Detailed Explanation

By default, Angular checks every component on every event. OnPush disables this and only runs change detection if an @Input reference changes, an event originated from the component or its children, or you manually call detectChanges(). This significantly improves performance.

Code Example
@Component({
    changeDetection: ChangeDetectionStrategy.OnPush
})
