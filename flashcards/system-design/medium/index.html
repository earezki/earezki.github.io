Backpressure in systems?

Quick Answer

Backpressure is a feedback mechanism where a consumer tells a producer to slow down because it cannot keep up with the data rate.

Detailed Explanation

Without backpressure, a fast producer will overwhelm a slow consumer's buffer, leading to OutOfMemory crashes. Systems like RxJava or reactive streams implement this to maintain stability.

Cachingstrategies

Cache-Aside (Lazy Loading) Strategy?

Quick Answer

App checks cache. If hit, return. If miss, fetch from DB, update cache, return.

Detailed Explanation

Pros: Only requested data is cached. Resilience (if cache fails, DB takes load). Cons: Cache miss penalty (3 trips). Data can become stale (needs TTL).

AvailabilityCAP

CAP Theorem?

Quick Answer

In a distributed system, you can only pick two: Consistency, Availability, Partition Tolerance.

Detailed Explanation

Since network partitions (P) are inevitable in distributed systems, you must choose between CP (return error if specific node down, but data always consistent) or AP (return potentially stale data, but always answer).

Database Sharding vs Partitioning?

Quick Answer

Sharding is horizontal partitioning of data across multiple database instances (physical servers), while partitioning often refers to splitting tables within the same instance.

Detailed Explanation

Sharding distributes the dataset so that no single machine holds all the data. It requires a Shard Key to determine which server holds the data. It allows massive scaling but disables complex joins and transactions across shards.

Eventual Consistency vs Strong Consistency?

Quick Answer

Strong consistency guarantees that a read returns the most recent write. Eventual consistency guarantees that if no new updates are made, all reads will eventually return the last written value.

Detailed Explanation

Strong consistency (e.g., SQL transactions) is slower and harder to scale. Eventual consistency (e.g., DNS, Cassandra) allows high availability and speed but requires the application to handle stale data temporarily.

Explain Rate Limiting algorithms.

Quick Answer

Rate limiting restricts the number of requests a user can make. Common algorithms include Token Bucket, Leaky Bucket, and Fixed Window.

Detailed Explanation

Token Bucket allows bursts of traffic (as long as tokens exist). Leaky Bucket processes requests at a constant release rate (smoothing bursts). These prevent DoS attacks and ensure fair usage.

CommunicationRPC

gRPC vs REST?

Quick Answer

REST uses JSON over HTTP/1.1. gRPC uses Protobuf (binary) over HTTP/2.

Detailed Explanation

gRPC is strictly typed, smaller, and faster (multiplexing). REST is human-readable and universally supported by browsers.

How do Message Queues (Kafka/RabbitMQ) help system design?

Quick Answer

They decouple producers from consumers, allowing asynchronous processing and load leveling.

Detailed Explanation

If an email service is down, the main app doesn't crash; it just queues the 'send email' message. The email service processes the queue when it recovers. It also smoothes out traffic spikes (buffering).

APIsDesign

Long Polling vs WebSockets?

Quick Answer

Long Polling: Client requests, Server holds connection open until data is available. WebSockets: bi-directional persistent connection.

Detailed Explanation

Long Polling is a hack over HTTP/1.1 for real-time. WebSockets is a true protocol. Use WebSockets for chat/games. Use Long Polling if legacy/firewall constraints exist.

ReplicationDatabase

Master-Slave Replication?

Quick Answer

One Master node handles Writes. Multiple Slave nodes handle Reads.

Detailed Explanation

Slaves sync data from Master (async or sync). Relieves read load from Master. If Master fails, a Slave can be promoted. Issue: Replication lag (reading stale data).

DiscoveryMicroservices

Service Discovery?

Quick Answer

The process of automatically detecting devices and services on a network.

Detailed Explanation

In cloud, IPs change dynamically. A Service Registry (like Eureka, Consul) keeps a live list. Client-side discovery (client asks registry) vs Server-side discovery (Load Balancer asks registry).

SecurityAuth

Session vs Token (JWT) Authentication?

Quick Answer

Session: Server stores state (Id) in memory/DB. Token: Client stores state (signed data).

Detailed Explanation

Sessions invalidate easily (delete from server) but require server memory/lookup. JWTs are stateless (great for microservices) but hard to revoke instantly.

HashingDesign

Short URL Design (TinyURL) - Key generation?

Quick Answer

Use Base62 encoding (A-Z, a-z, 0-9) on a unique ID.

Detailed Explanation

With 7 chars of Base62, you get $62^7$ (~3.5 trillion) combinations. Use a centralized ID generator (Snowflake) or DB auto-increment to get the unique integer ID, then convert to Base62.

Single Point of Failure (SPOF) and how to avoid it?

Quick Answer

An SPOF is a part of a system that, if it fails, stops the entire system from working.

Detailed Explanation

To avoid SPOF, introduce redundancy at every layer: multiple API servers behind a load balancer, master-slave database replication, and multi-region deployments.

What is an API Gateway?

Quick Answer

It is an entry point for all clients, acting as a reverse proxy that routes requests to appropriate microservices.

Detailed Explanation

Besides routing, it handles cross-cutting concerns like Authentication, SSL Termination, Rate Limiting, Request Transformation, and Logging so that individual services don't have to.

What is Consistent Hashing?

Quick Answer

A technique used in distributed systems to minimize data reorganization when nodes are added or removed to a cluster.

Detailed Explanation

With simple modulo hashing (hash(key) % N), adding a server changes N and re-maps almost all keys. Consistent hashing maps both keys and servers to a ring. Adding a node only affects the keys in its immediate segment, drastically reducing reshuffling. Used in Cassandra, DynamoDB, etc.

DatabaseSharding

What is Database Sharding?

Quick Answer

Horizontal scaling of a database by partitioning data across multiple machines.

Detailed Explanation

Instead of one huge Users table, you split it. Users A-M go to DB1, N-Z go to DB2. Challenges: Joins across shards are hard, and rebalancing data is complex.

What is Idempotency?

Quick Answer

An operation is idempotent if applying it multiple times has the same effect as applying it once.

Detailed Explanation

Crucial in distributed systems where networks fail. If a client retries a 'Pay $10' request because of a timeout, the server must ensure $10 is deducted only once. GET, PUT, and DELETE are typically idempotent; POST is not.

What is the CAP Theorem?

Quick Answer

It states that a distributed system can only provide two of the three guarantees: Consistency, Availability, and Partition Tolerance.

Detailed Explanation

In a network partition scenario (P), you must choose between Consistency (all nodes see the same data, but might reject requests if out of sync) or Availability (system always responds, but data might be stale). You cannot have both perfect consistency and 100% availability in a distributed network that can drop packets.

Cachingstrategies

Write-Through vs Write-Back Caching?

Quick Answer

Write-Through: Write to cache and DB simultaneously (safe, slow write). Write-Back: Write to cache only; cache updates DB later (fast write, risk of data loss).

Detailed Explanation

Write-Back is great for write-heavy workloads where durability can be slightly compromised for speed.
