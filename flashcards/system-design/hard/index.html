ACID vs BASE transactions?

Quick Answer

ACID (Atomicity, Consistency, Isolation, Durability) guarantees strict transactions. BASE (Basically Available, Soft state, Eventual consistency) prioritizes availability over consistency.

Detailed Explanation

NoSQL systems often follow BASE. Instead of locking rows (ACID), they allow data to be 'soft' (changing) and resolve conflicts later (Eventual consistency), enabling higher write throughput at the cost of transient inconsistency.

Big DataProcessing

Batch vs Stream Processing (Lambda Architecture)?

Quick Answer

Lambda Architecture has two layers: Batch (Hadoop/Spark) for accuracy/history, Speed (Storm/Flink/Kafka) for real-time.

Detailed Explanation

Batch layer re-computes everything nightly (correcting errors). Speed layer handles last 24h. Query layer merges results. Kappa Architecture removes Batch layer (everything is a stream).

DesignNewsfeed

Design Facebook Newsfeed (Fan-out)?

Quick Answer

Fan-out on Write (Push) vs Fan-out on Read (Pull).

Detailed Explanation

Push: When User posts, push ID to all followers' feeds (Fast read, slow write for celebs). Pull: When User reads feed, query friends' posts (Slow read, fast write). Hybrid approach is best.

Design Whatsapp (Key Challenges)?

Quick Answer

Real-time delivery, Presence (Online/Offline), Message Ordering, End-to-End Encryption.

Use WebSockets (Erlang/Elixir is good). Store offline messages in HBase/Cassandra. Use Signal Protocol for encryption (Double Ratchet). Push Notifications for offline users.

IdempotencyPayments

Designing a Payment System?

Quick Answer

Crucial: ACID transactions, Idempotency, Double-entry bookkeeping.

Detailed Explanation

Never use float for money. Use Idempotency Keys to prevent double charge on retry. Implement Two-Phase Commit (2PC) or Sagas if spanning multiple services.

Distributed Rate Limiter Algorithm?

Quick Answer

Token Bucket or Leaky Bucket algorithm.

Detailed Explanation

In distributed env, use Redis + Lua script to atomically decrement tokens. 'Fixed Window' has edge cases (double burst). 'Sliding Window Log' is expensive. 'Sliding Window Counter' is balanced.

Explain 'Split-Brain' in distributed systems.

Quick Answer

A condition where a network partition causes two sets of nodes in a cluster to believe they are the legitimate master/leader, leading to data corruption.

Detailed Explanation

This happens when the heartbeat link fails. Both sides promote a master and accept writes independently. To prevent this, a 'Quorum' (majority vote > 50%) is required to elect a leader. If a set of nodes has < 50% members, it stops accepting writes.

Spatial Indexing to find 'drivers near me'.

QuadTree recursively divides 2D space into 4 squares. GeoHash encodes lat/long into a string. Nearby points share common prefix. Used for fast proximity search.

How Search Engines work (Inverted Index)?

Quick Answer

Mapping content (words) to its location (document IDs).

Detailed Explanation

Instead of scanning docs for 'Apple', you look up 'Apple' in the index -> gets list [Doc1, Doc5]. Intersection of lists provides multi-word search. ElasticSearch uses this (Lucene).

How to check uniqueness of 1 Billion usernames efficiently?

Quick Answer

Bloom Filter.

Leader Election algorithms (Paxos vs Raft)?

Quick Answer

Algorithms used to agree on a single leader in a distributed cluster to coordinate changes.

Detailed Explanation

Paxos is the original consensus algorithm but is notoriously difficult to implement. Raft was designed for understandability. Raft uses a 'strong leader' approach where log entries only flow from leader to followers, simplifying the consensus logic.

ConsensusDistributed

Paxos or Raft?

Quick Answer

Consensus algorithms to agree on a value in a distributed system (Leader Election).

Detailed Explanation

Raft is designed to be understandable. It relies on a strong Leader. Log Replication ensures all nodes have same state. Used in Etcd, Consul, Kubernetes.

Saga Pattern for Distributed Transactions?

Quick Answer

A pattern to manage long-running transactions spanning multiple microservices.

Detailed Explanation

Since 2-Phase Commit (2PC) blocks and scales poorly, Saga breaks the transaction into a sequence of local transactions. If one fails, it executes 'compensating transactions' (undo steps) to roll back the changes in previous services eventually.

CacheStampede

Thundering Herd Problem (Cache Stampede)?

Quick Answer

When a popular cache item expires, thousands of requests hit the DB simultaneously.

Detailed Explanation

Solutions: 1. Probabilistic Early Expiration (Jitter). 2. Mutex/Locking (Only one process builds cache). 3. Keep stale value while background process updates.

Thundering Herd Problem?

Quick Answer

A phenomenon where a large number of processes wake up simultaneously to handle an event (like a cache expiry), overwhelming the system.

Detailed Explanation

If a popular cache item expires, thousands of requests hit the DB at once. Solutions include 'Cache Stampede' protection (locking the cache key so only one recalculates) or adding jitter (randomness) to expiration times.

What are Bloom Filters and HyperLogLog?

Quick Answer

Probabilistic data structures. Bloom Filters test if an element is definitely not in a set or maybe in it. HyperLogLog estimates the cardinality (count of unique items) of a massive set.

Detailed Explanation

They use extremely small memory compared to storing the actual data. Use Bloom Filters to quickly check if a username is taken (avoiding DB lookup if not). Use HyperLogLog to count unique visitors to a website (DAU) with 99% accuracy using only KBs of memory.

What is a Gossip Protocol?

Quick Answer

A peer-to-peer communication protocol where nodes share information about themselves and other nodes randomly, like a virus spreading.

Detailed Explanation

It is used for failure detection and membership management in decentralized clusters (like Cassandra or DynamoDB). It is robust, scalable (O(log N)), and resilient to network partitions, ensuring state eventually converges across the cluster.

What is Database Isolation Levels (Read Committed vs Serializable)?

Quick Answer

Isolation levels define how visible uncommitted changes are to other transactions. 'Read Committed' prevents dirty reads. 'Serializable' is the strictest, making transactions appear sequential.

Detailed Explanation

Lower isolation levels (Read Uncommitted) are faster but risk data anomalies (dirty reads, phantom reads). Higher levels (Serializable) use heavy locking or MVCC (Multi-Version Concurrency Control) to ensure correctness but reduce concurrency.

What is Geohashing / Quadtrees?

Quick Answer

Spatial indexing techniques to efficiently query location-based data (e.g., 'find Uber drivers near me').

Detailed Explanation

Geohashing encodes 2D (lat/long) coordinates into a string. Points sharing a prefix are close together. Quadtrees recursively divide a 2D space into four quadrants. These structures allow fast 'k-nearest-neighbors' searches without scanning the entire database.

What is Vector Clock?

Quick Answer

A logical clock mechanism used to determine the partial ordering of events in a distributed system and detect causality violations.

Detailed Explanation

Unlike wall clocks (timestamps) which drift, vector clocks track the 'version' of data across different nodes (e.g., [NodeA:1, NodeB:2]). They help resolving merge conflicts (like in DynamoDB) by identifying if one version is an ancestor of another or if they are concurrent conflicts.
