Compare asyncio concurrency vs threading.

Quick Answer

threading is preemptive multitasking (OS switches threads) suitable for I/O bound tasks but limited by GIL. asyncio is cooperative multitasking (single thread, explicit yields).

Detailed Explanation

asyncio uses an event loop and coroutines (async/await). It is extremely efficient for massive I/O concurrency (like thousands of network connections) because it avoids the overhead of OS context switching. However, blocking the event loop freezes the entire app.

Explain deep copy vs shallow copy.

Quick Answer

Shallow copy creates a new object but references the same child objects; deep copy recursively copies child objects.

Detailed Explanation

A shallow copy creates a new compound object and inserts references into it to the objects found in the original. A deep copy creates a new compound object and then, recursively, inserts copies into it of the objects found in the original. Core functionality: shallow copy for performance when shared references are acceptable; deep copy for complete independence. Internal mechanics: shallow copy uses copy.copy(); deep copy uses copy.deepcopy() with memoization to handle cycles. Recommended practices: use shallow copy by default, deep copy only when needed, be aware of custom copy and deepcopy methods. Common mistakes: modifying shared objects unintentionally after shallow copy, or creating infinite recursion in deep copy. Practical use cases: copying configuration objects, duplicating data structures, implementing undo functionality. Performance implications: shallow copy is fast and memory-efficient; deep copy can be expensive for large or complex objects.

Code Example
import copy
from typing import List, Dict, Any

class Person:
    """A person class with nested objects"""
    def __init__(self, name: str, address: Dict[str, str]):
        self.name = name
        self.address = address
    
    def __repr__(self):
        return f"Person({self.name}, {self.address})"

# Demonstrate shallow vs deep copy
def demonstrate_copying():
    """Show the difference between shallow and deep copy"""
    try:
        # Create original object
        original_address = {"street": "123 Main St", "city": "Anytown"}
        original_person = Person("John", original_address)
        
        # Shallow copy
        shallow_copy = copy.copy(original_person)
        
        # Deep copy
        deep_copy = copy.deepcopy(original_person)
        
        print("Original:", original_person)
        print("Shallow copy:", shallow_copy)
        print("Deep copy:", deep_copy)
        
        # Modify the address
        original_person.address["city"] = "Newtown"
        
        print("\nAfter modifying original address:")
        print("Original:", original_person)
        print("Shallow copy:", shallow_copy)  # Changed!
        print("Deep copy:", deep_copy)        # Unchanged
        
    except Exception as e:
        print(f"Error in copying demonstration: {e}")

# Custom copy methods
def demonstrate_custom_copy():
    """Show custom __copy__ and __deepcopy__ methods"""
    class CustomList:
        """A list with custom copy behavior"""
        def __init__(self, items: List[Any]):
            self.items = items
        
        def __copy__(self):
            print("Shallow copy called")
            return CustomList(self.items.copy())
        
        def __deepcopy__(self, memo):
            print("Deep copy called")
            return CustomList(copy.deepcopy(self.items, memo))
        
        def __repr__(self):
            return f"CustomList({self.items})"
    
    try:
        original = CustomList([1, [2, 3], 4])
        shallow = copy.copy(original)
        deep = copy.deepcopy(original)
        
        print(f"Original: {original}")
        print(f"Shallow: {shallow}")
        print(f"Deep: {deep}")
        
    except Exception as e:
        print(f"Error in custom copy demonstration: {e}")

# Handling circular references
def demonstrate_circular():
    """Show how deepcopy handles circular references"""
    class Node:
        """A node that can reference itself"""
        def __init__(self, value: Any):
            self.value = value
            self.ref = None
        
        def __repr__(self):
            return f"Node({self.value})"
    
    try:
        node1 = Node(1)
        node2 = Node(2)
        node1.ref = node2
        node2.ref = node1  # Circular reference
        
        # This would work with deepcopy due to memoization
        copied_node1 = copy.deepcopy(node1)
        print(f"Original node1.ref.ref is node1: {node1.ref.ref is node1}")
        print(f"Copied node1.ref.ref is copied_node1: {copied_node1.ref.ref is copied_node1}")
        
    except Exception as e:
        print(f"Error in circular reference demonstration: {e}")

# Performance comparison
def performance_comparison():
    """Compare performance of shallow vs deep copy"""
    import time
    
    large_list = [[i for i in range(100)] for _ in range(100)]
    
    try:
        # Shallow copy
        start = time.time()
        for _ in range(1000):
            copy.copy(large_list)
        shallow_time = time.time() - start
        
        # Deep copy
        start = time.time()
        for _ in range(1000):
            copy.deepcopy(large_list)
        deep_time = time.time() - start
        
        print(f"Shallow copy time: {shallow_time:.4f}s")
        print(f"Deep copy time: {deep_time:.4f}s")
        print(f"Deep copy is {deep_time/shallow_time:.1f}x slower")
        
    except Exception as e:
        print(f"Error in performance comparison: {e}")

# Run demonstrations
demonstrate_copying()
print()
demonstrate_custom_copy()
print()
demonstrate_circular()
print()

How do you create a decorator that accepts arguments?

Quick Answer

You need a three-level wrapper function.

Detailed Explanation

A decorator that accepts arguments requires three levels of nested functions: an outer function that takes the decorator arguments, a middle function that takes the function to be decorated, and an inner function that acts as the wrapper. This allows syntax like @decorator(arg1, arg2). Core functionality includes modifying function behavior with parameters. Internal mechanics involve the decorator being called with arguments first, returning a decorator function that then wraps the target function. Recommended practices include using functools.wraps to preserve metadata, and considering class-based decorators for complex cases. Common mistakes include forgetting the third level of nesting or not handling arguments correctly. Practical use cases include logging with levels, caching with timeouts, and retry mechanisms with attempt limits. Performance implications: Decorators add minimal overhead but can be called frequently; for performance-critical code, consider alternatives like direct function calls.

Code Example
import functools
import time
from typing import Callable, Any

def retry(max_attempts: int, delay: float = 1.0):
    """Decorator that retries a function on failure"""
    def decorator_retry(func: Callable) -> Callable:
        @functools.wraps(func)
        def wrapper_retry(*args, **kwargs) -> Any:
            attempts = 0
            while attempts < max_attempts:
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    attempts += 1
                    if attempts == max_attempts:
                        raise e
                    print(f"Attempt {attempts} failed: {e}. Retrying in {delay}s...")
                    time.sleep(delay)
            return None
        return wrapper_retry
    return decorator_retry

@retry(max_attempts=3, delay=0.5)
def unstable_function():
    """Simulate an unstable function that may fail"""
    import random
    if random.random() < 0.7:  # 70% chance of failure
        raise ValueError("Random failure")
    return "Success!"

# Another example: Caching decorator
def cache(max_size: int = 100):
    """Simple LRU cache decorator"""
    def decorator_cache(func: Callable) -> Callable:
        cache_dict = {}
        order = []
        
        @functools.wraps(func)
        def wrapper_cache(*args, **kwargs) -> Any:
            key = str(args) + str(sorted(kwargs.items()))
            if key in cache_dict:
                return cache_dict[key]
            
            result = func(*args, **kwargs)
            
            if len(cache_dict) >= max_size:
                # Remove oldest
                oldest_key = order.pop(0)
                del cache_dict[oldest_key]
            
            cache_dict[key] = result
            order.append(key)
            return result
        
        return wrapper_cache
    return decorator_cache

@cache(max_size=5)
def expensive_computation(n: int) -> int:
    """Simulate expensive computation"""
    time.sleep(0.1)  # Simulate delay
    return n * n

# Usage with error handling:
try:
    result1 = unstable_function()
    print(f"Result: {result1}")
    
    result2 = expensive_computation(5)
    print(f"Cached result: {result2}")
    
    # Call again - should use cache
    result3 = expensive_computation(5)
    print(f"Cached result again: {result3}")
    
except Exception as e:
    print(f"Error: {e}")

How does Python manage memory?

Quick Answer

Through private heap space and reference counting, supplemented by a cyclic garbage collector.

Detailed Explanation

Python manages memory using a private heap space where all Python objects and data structures are stored. The primary mechanism is reference counting: each object has a count of references pointing to it, and when this count reaches zero, the object is deallocated immediately. However, reference counting cannot handle circular references (e.g., A references B, B references A). To address this, Python includes a cyclic garbage collector that runs periodically to detect and break reference cycles. Core functionality includes automatic memory management without manual allocation/deallocation. Internal mechanics involve the reference counter being incremented/decremented on assignment, and the cyclic GC using generational collection. Recommended practices include avoiding circular references where possible, using weak references for caches, and being mindful of large data structures. Common mistakes include creating reference cycles unintentionally, leading to memory leaks, or assuming immediate cleanup. Practical use cases include web applications, data processing scripts, and long-running services. Performance implications: Reference counting provides fast deallocation but can cause pauses during cyclic GC; overall, Python's memory management is efficient for most applications but may require tuning for high-performance scenarios.

Code Example
import sys
import gc
from typing import List

class Node:
    """A simple node class that can create reference cycles"""
    def __init__(self, value: Any):
        self.value = value
        self.children: List[Node] = []
    
    def add_child(self, child: Node):
        self.children.append(child)
        child.parent = self  # Creates a reference cycle

# Demonstrate reference counting
def demonstrate_refcount():
    """Show how reference counting works"""
    a = [1, 2, 3]
    print(f"Initial refcount: {sys.getrefcount(a)}")
    
    b = a  # Increase refcount
    print(f"After assignment: {sys.getrefcount(a)}")
    
    del b  # Decrease refcount
    print(f"After deletion: {sys.getrefcount(a)}")

# Demonstrate cyclic garbage collection
def demonstrate_cycles():
    """Show how cyclic GC handles reference cycles"""
    try:
        parent = Node("parent")
        child = Node("child")
        parent.add_child(child)
        
        # Create cycle
        del parent
        del child
        
        # Force garbage collection
        collected = gc.collect()
        print(f"Objects collected by GC: {collected}")
        
    except Exception as e:
        print(f"Error in cycle demonstration: {e}")

# Using weak references to avoid cycles
import weakref

def demonstrate_weakref():
    """Show weak references for caches"""
    class Cache:
        def __init__(self):
            self._cache = weakref.WeakKeyDictionary()
        
        def set(self, key, value):
            self._cache[key] = value
        
        def get(self, key):
            return self._cache.get(key)
    
    try:
        cache = Cache()
        obj = Node("temp")
        cache.set(obj, "cached_value")
        
        print(f"Cached value: {cache.get(obj)}")
        
        del obj  # Object can be garbage collected
        print(f"After deletion: {cache.get(obj)}")  # None
        
    except Exception as e:
        print(f"Error in weakref demonstration: {e}")

# Run demonstrations
demonstrate_refcount()
demonstrate_cycles()
demonstrate_weakref()

What is __slots__ used for?

Quick Answer

To restrict valid attributes and save memory.

Detailed Explanation

slots is a class attribute that allows you to explicitly declare data members and deny the creation of dict and weakref for instances. This restricts the attributes that can be assigned to instances and can save memory. Core functionality: memory optimization and attribute restriction. Internal mechanics: replaces dict with a fixed-size array, preventing dynamic attribute creation. Recommended practices: use for classes with many instances and few attributes, document restrictions, consider inheritance implications. Common mistakes: forgetting inherited slots, trying to add dict after defining slots, or using with classes needing dynamic attributes. Practical use cases: large datasets, performance-critical code, immutable objects. Performance implications: faster attribute access, lower memory usage (up to 50% less), but slower class creation and modification.

Code Example
import sys
from typing import List

class RegularClass:
    """A regular class with __dict__"""
    def __init__(self, x: int, y: int):
        self.x = x
        self.y = y

class SlottedClass:
    """A class using __slots__"""
    __slots__ = ['x', 'y']
    
    def __init__(self, x: int, y: int):
        self.x = x
        self.y = y

# Demonstrate memory usage
def demonstrate_memory_usage():
    """Compare memory usage between regular and slotted classes"""
    try:
        regular_instances = [RegularClass(i, i*2) for i in range(10000)]
        slotted_instances = [SlottedClass(i, i*2) for i in range(10000)]
        
        regular_memory = sum(sys.getsizeof(inst) for inst in regular_instances)
        slotted_memory = sum(sys.getsizeof(inst) for inst in slotted_instances)
        
        print(f"Regular class memory: {regular_memory} bytes")
        print(f"Slotted class memory: {slotted_memory} bytes")
        print(f"Memory savings: {(regular_memory - slotted_memory) / regular_memory * 100:.1f}%")
        
    except Exception as e:
        print(f"Error in memory demonstration: {e}")

# Demonstrate attribute restriction
def demonstrate_attribute_restriction():
    """Show how __slots__ restricts attributes"""
    try:
        obj = SlottedClass(1, 2)
        print(f"x: {obj.x}, y: {obj.y}")
        
        # This should work
        obj.x = 10
        print(f"Modified x: {obj.x}")
        
        # This should fail
        obj.z = 3  # AttributeError
        
    except AttributeError as e:
        print(f"Attribute restriction error: {e}")
    except Exception as e:
        print(f"Unexpected error: {e}")

# Inheritance with __slots__
def demonstrate_inheritance():
    """Show __slots__ in inheritance"""
    class BaseWithSlots:
        __slots__ = ['a']
        
        def __init__(self, a):
            self.a = a
    
    class DerivedWithSlots(BaseWithSlots):
        __slots__ = ['b']  # Only adds b, inherits a
        
        def __init__(self, a, b):
            super().__init__(a)
            self.b = b
    
    class DerivedWithDict(BaseWithSlots):
        # No __slots__, so has __dict__
        pass
    
    try:
        derived_slots = DerivedWithSlots(1, 2)
        derived_dict = DerivedWithDict(1)
        
        print(f"Derived with slots: a={derived_slots.a}, b={derived_slots.b}")
        print(f"Derived with dict: a={derived_dict.a}")
        
        # Can add dynamic attributes to derived_dict
        derived_dict.c = 3
        print(f"Dynamic attribute: {derived_dict.c}")
        
    except Exception as e:
        print(f"Error in inheritance demonstration: {e}")

# Performance comparison
def performance_comparison():
    """Compare attribute access performance"""
    import time
    
    regular = RegularClass(1, 2)
    slotted = SlottedClass(1, 2)
    
    # Test attribute access
    iterations = 1000000
    
    try:
        # Regular class
        start = time.time()
        for _ in range(iterations):
            _ = regular.x
        regular_time = time.time() - start
        
        # Slotted class
        start = time.time()
        for _ in range(iterations):
            _ = slotted.x
        slotted_time = time.time() - start
        
        print(f"Regular access time: {regular_time:.4f}s")
        print(f"Slotted access time: {slotted_time:.4f}s")
        print(f"Slotted is {regular_time/slotted_time:.1f}x faster")
        
    except Exception as e:
        print(f"Error in performance comparison: {e}")

demonstrate_inheritance()

What is a Descriptor in Python?

Quick Answer

An object that manages the attributes of another object.

Detailed Explanation

A descriptor is any object that implements at least one of the methods get, set, or delete. These methods allow you to customize attribute access on instances of a class. Descriptors are the mechanism behind properties, methods, static methods, and class methods. Core functionality includes controlling how attributes are accessed, set, or deleted. Internal mechanics: when an attribute is accessed, Python checks if the attribute's value is a descriptor and calls the appropriate method. Recommended practices: use descriptors for reusable property logic, document their behavior, and consider property() for simple cases. Common mistakes: forgetting to return self in get for non-data descriptors, or creating infinite recursion. Practical use cases: lazy loading, validation, computed properties, and type checking. Performance implications: descriptors add a small overhead on attribute access but enable powerful abstractions; use judiciously in performance-critical code.

Code Example
from typing import Any

class LazyProperty:
    """A descriptor for lazy property evaluation"""
    def __init__(self, func):
        self.func = func
        self.name = func.__name__
    
    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        try:
            value = obj.__dict__[self.name]
        except KeyError:
            value = self.func(obj)
            obj.__dict__[self.name] = value
        return value
    
    def __set__(self, obj, value):
        obj.__dict__[self.name] = value

class ValidatedAttribute:
    """A descriptor for attribute validation"""
    def __init__(self, validator=None):
        self.validator = validator
    
    def __set_name__(self, owner, name):
        self.name = name
    
    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return obj.__dict__.get(self.name, None)
    
    def __set__(self, obj, value):
        if self.validator and not self.validator(value):
            raise ValueError(f"Invalid value for {self.name}: {value}")
        obj.__dict__[self.name] = value

class Person:
    """A class using descriptors"""
    age = ValidatedAttribute(lambda x: isinstance(x, int) and x > 0)
    
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age
    
    @LazyProperty
    def display_name(self):
        """Lazy property that capitalizes the name"""
        print(f"Computing display_name for {self.name}")
        return self.name.title()

# Usage with error handling:

    print(f"Name: {person.display_name}")  # Computed once
    print(f"Name again: {person.display_name}")  # Cached

What is a Metaclass in Python?

Quick Answer

A class of a class, or a blueprint for creating classes.

Detailed Explanation

A metaclass in Python is a class whose instances are classes themselves. Just as an object is an instance of a class, a class is an instance of a metaclass. The default metaclass is type, but you can create custom metaclasses by inheriting from type. Core functionality includes controlling class creation, modifying class attributes, and enforcing coding standards. Internal mechanics involve the __new__ and __init__ methods of the metaclass being called during class definition. Recommended practices include using metaclasses sparingly, only when you need to modify class behavior globally, and documenting their use clearly. Common mistakes include overusing metaclasses for simple problems that can be solved with decorators or inheritance, leading to complex and hard-to-debug code. Practical use cases include ORM frameworks (like Django models), API frameworks, and enforcing coding standards across a codebase. Performance implications: Metaclasses add overhead during class creation but have negligible impact at runtime; they can improve code organization and reduce boilerplate.

Code Example
from typing import Any

class SingletonMeta(type):
    """A metaclass for creating singleton classes"""
    _instances = {}
    
    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class DatabaseConnection(metaclass=SingletonMeta):
    """A singleton database connection class"""
    def __init__(self, host: str = 'localhost', port: int = 5432):
        self.host = host
        self.port = port
        print(f"Connecting to database at {host}:{port}")
    
    def query(self, sql: str) -> str:
        """Simulate a database query"""
        return f"Result for: {sql}"

# Usage:
try:
    db1 = DatabaseConnection('prod-db', 5432)
    db2 = DatabaseConnection('dev-db', 5432)  # This will return the same instance
    
    print(db1 is db2)  # True - same instance
    print(db1.query("SELECT * FROM users"))
    
except Exception as e:
    print(f"Error creating database connection: {e}")

class ValidatedMeta(type):
    def __new__(cls, name, bases, dct):
        # Ensure all classes have a 'validate' method
        if 'validate' not in dct:
            raise TypeError(f"Class {name} must have a 'validate' method")
        return super().__new__(cls, name, bases, dct)

class UserModel(metaclass=ValidatedMeta):
    def __init__(self, name: str, email: str):
        self.name = name
        self.email = email
    
    def validate(self) -> bool:
        """Validate user data"""
        return bool(self.name and '@' in self.email)

try:
    user = UserModel("John", "john@example.com")
    print(f"User valid: {user.validate()}")
except TypeError as e:
    print(f"Metaclass validation error: {e}")

What is Monkey Patching?

Quick Answer

Dynamically modifying a class or module at runtime.

Detailed Explanation

Monkey patching refers to the dynamic modification of a class or module at runtime, typically by replacing methods or attributes. This allows changing the behavior of code without modifying the source. Core functionality: runtime code modification for testing, debugging, or extending libraries. def demonstrate_basic_patching():
    """Show basic monkey patching"""

def demonstrate_context_manager():
    """Show custom context manager for patching"""
    from contextlib import contextmanager
    
    @contextmanager
    def patch_attribute(obj, attr, new_value):
        """Context manager for temporarily patching attributes"""

        setattr(obj, attr, new_value)

            yield
        finally:

            print(f"Patched DEBUG: {Config.DEBUG}")
        
        print(f"Restored DEBUG: {Config.DEBUG}")
        
    except Exception as e:
        print(f"Error in context manager: {e}")

What is the difference between threading and asyncio?

Quick Answer

Threading uses preemptive multitasking; asyncio uses cooperative multitasking.

Detailed Explanation

Threading in Python uses preemptive multitasking where the operating system decides when to switch between threads, allowing multiple threads to run concurrently and share memory. Asyncio uses cooperative multitasking where tasks voluntarily yield control using 'await', running on a single thread with an event loop managing task switching. Core functionality: threading for CPU parallelism (limited by GIL) and I/O concurrency; asyncio for efficient I/O-bound concurrency. Internal mechanics: threading relies on OS scheduling and GIL; asyncio uses coroutines and an event loop. Recommended practices: use asyncio for I/O-heavy applications, threading for CPU tasks with multiprocessing, avoid mixing paradigms. Common mistakes: using threading for I/O when asyncio is better, or forgetting to await coroutines. Practical use cases: web servers, data pipelines, GUI applications. Performance implications: asyncio often more efficient for high concurrency due to lower overhead; threading can be simpler but may have more context-switching overhead.

Code Example

import threading
import time
from typing import List

# Asyncio example
def fibonacci_async(n: int) -> int:
    """Calculate fibonacci asynchronously (simulated)"""
    if n <= 1:
        return n
    return fibonacci_async(n-1) + fibonacci_async(n-2)

async def async_task(task_id: int, duration: float):
    """Simulate an async I/O task"""
    print(f"Async task {task_id} starting")
    await asyncio.sleep(duration)  # Simulate I/O
    result = fibonacci_async(30)  # CPU work
    print(f"Async task {task_id} completed")
    return result

async def run_asyncio_example():
    """Run multiple async tasks concurrently"""
    try:
        tasks = [async_task(i, 0.1) for i in range(5)]
        results = await asyncio.gather(*tasks)
        print(f"Async results: {results}")
    except Exception as e:
        print(f"Async error: {e}")

# Threading example
def thread_task(task_id: int, duration: float, results: List[int]):
    """Simulate a threaded task"""
    print(f"Thread {task_id} starting")
    time.sleep(duration)  # Blocking sleep
    result = fibonacci_async(30)  # CPU work
    results.append(result)
    print(f"Thread {task_id} completed")

def run_threading_example():
    """Run multiple threads"""
    try:
        threads = []
        results = []
        for i in range(5):
            t = threading.Thread(target=thread_task, args=(i, 0.1, results))
            threads.append(t)
            t.start()

            t.join()

    except Exception as e:

What is the Global Interpreter Lock (GIL)?

Quick Answer

A mutex that allows only one thread to hold the control of the Python interpreter.

Detailed Explanation

The Global Interpreter Lock (GIL) is a mechanism in CPython, the reference implementation of Python, that synchronizes the execution of threads so that only one native thread can execute Python bytecodes at a time. This lock is necessary because CPython's memory management is not thread-safe. Core functionality includes preventing race conditions in Python's internal data structures. Internal mechanics involve acquiring and releasing the lock around bytecode execution, with threads yielding the GIL during I/O operations or when explicitly releasing it. Recommended practices include using multiprocessing for CPU-bound tasks instead of threading, or using asyncio for I/O-bound concurrency. Common mistakes include assuming threading provides true parallelism for CPU-intensive work, leading to performance bottlenecks. Practical use cases involve web servers handling multiple I/O operations concurrently. Performance implications: GIL can limit CPU utilization in multithreaded programs, but for I/O-bound tasks, the overhead is minimal as threads release the GIL during blocking operations.

def run_with_threads():
    """Demonstrate threading with GIL limitation"""

        processes.append(p)
        p.start()
    
    for p in processes:
        p.join()

What is the Method Resolution Order (MRO)?

Quick Answer

The order in which Python searches for a method in a hierarchy of classes.

Detailed Explanation

The Method Resolution Order (MRO) is the sequence in which Python looks for a method or attribute in a class hierarchy during inheritance. Python uses the C3 linearization algorithm (also known as C3 superclass linearization) to compute the MRO, ensuring a consistent and predictable order. Core functionality includes resolving method calls in multiple inheritance scenarios. Internal mechanics: C3 algorithm creates a linear order that preserves the inheritance hierarchy while avoiding the diamond problem. Recommended practices: use MRO to understand inheritance, avoid complex multiple inheritance, and use super() correctly. Common mistakes: assuming left-to-right resolution or creating inheritance diamonds without understanding MRO. Practical use cases: mixin classes, cooperative inheritance, and framework design. Performance implications: MRO computation happens at class creation time, so no runtime overhead; complex hierarchies may increase lookup time slightly.

        return "Feeding milk"

        print("MRO for Platypus:")
