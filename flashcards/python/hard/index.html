__getattr__ vs __getattribute__?

Quick Answer

__getattribute__ is called for every attribute access; __getattr__ only if it's not found.

Detailed Explanation

__getattribute__ intercepts every dot access, making it powerful but dangerous (prone to infinite recursion). __getattr__ is a fallback mechanism for missing attributes.

Code Example
class A:
    def __getattr__(self, name):
        return f"{name} not found!"

__new__ vs __init__?

Quick Answer

__new__ creates the object; __init__ initializes it.

Detailed Explanation

__new__ is a static method that handles the creation logic (memory allocation). __init__ is an instance method called after the object is created to set initial attributes. You rarely override __new__ unless subclassing immutable types like tuple.

Code Example
class A:
    def __new__(cls):
        print("Creating")
        return super().__new__(cls)
    def __init__(self):
        print("Init")

Detailed Explanation

Due to GIL, threading is good for I/O bound tasks. multiprocessing creates separate memory spaces and bypasses GIL, making it good for CPU bound tasks.

Compare asyncio concurrency vs threading.

Quick Answer

threading is preemptive multitasking (OS switches threads) suitable for I/O bound tasks but limited by GIL. asyncio is cooperative multitasking (single thread, explicit yields).

Detailed Explanation

asyncio uses an event loop and coroutines (async/await). It is extremely efficient for massive I/O concurrency (like thousands of network connections) because it avoids the overhead of OS context switching. However, blocking the event loop freezes the entire app.

Code Example

async def main():
await asyncio.sleep(1)

Quick Answer

The contextlib.contextmanager decorator converts a generator function into a context manager.

Detailed Explanation

It simplifies creating context managers without writing a full class with __enter__ and __exit__. You yield the resource; code before yield is setup, code after yield is teardown (in a finally block).

finally:

CPU-bound vs I/O-bound in Python?

Quick Answer

CPU-bound tasks spend time calculating (math, processing). I/O-bound tasks wait for external resources (network, disk).

Detailed Explanation

Due to the GIL, standard threading doesn't help CPU-bound tasks (use multiprocessing instead). threading or asyncio works great for I/O-bound tasks because the GIL is released while waiting for I/O.

Explain deep copy vs shallow copy.

Quick Answer

Shallow copy creates a new object but references the same child objects; deep copy recursively copies child objects.

Detailed Explanation

A shallow copy constructs a new compound object and inserts references into it to the objects found in the original. A deep copy constructs a new compound object and then, recursively, inserts copies into it of the objects found in the original.

Code Example
import copy
x = [[1, 2], [3, 4]]
y = copy.copy(x)      # Shallow
z = copy.deepcopy(x)  # Deep

Explain the Method Resolution Order (MRO).

Quick Answer

MRO is the order in which Python looks for a method in a hierarchy of classes. Python uses the C3 Linearization algorithm.

Detailed Explanation

In multiple inheritance, complex diamond patterns can occur. The MRO ensures that a class is always checked before its parents, and parents are checked in a consistent order that respects the inheritance declaration order (left-to-right). You can check it via Class.__mro__.

Code Example

class D(B, C): pass
print(D.mro)

How do you create a decorator that accepts arguments?

Quick Answer

You need a three-level wrapper function.

Detailed Explanation

To pass arguments to the decorator itself (like @repeat(3)), you need an outer function that takes the arguments, a middle function that takes the function to be decorated, and an inner function that behaves as the wrapper.

Code Example
def repeat(num):
    def decorator_repeat(func):
        def wrapper(*args, **kwargs):
            for _ in range(num):
                func(*args, **kwargs)
        return wrapper
    return decorator_repeat

@repeat(3)
def hello():
    print("Hi")

How does Python manage memory?

Quick Answer

Through private heap space and reference counting, supplemented by a cyclic garbage collector.

Detailed Explanation

Python uses reference counting to deallocate objects when their reference count drops to zero. However, reference counting cannot handle reference cycles (A references B, B references A). To handle this, Python has a cyclic garbage collector that periodically detects and cleans up circular references.

Code Example

What is the difference between threading and asyncio?

Quick Answer

Threading uses preemptive multitasking; asyncio uses cooperative multitasking.

Detailed Explanation

In threading, the OS decides when to switch tasks, and multiple threads share memory. In asyncio, the code itself decides when to yield control (using await), running on a single thread with an event loop. Asyncio is typically more efficient for I/O-bound tasks with many connections.

Code Example

    print('Hello')
    await asyncio.sleep(1)
    print('World')

What is the Method Resolution Order (MRO)?

Quick Answer

The order in which Python searches for a method in a hierarchy of classes.

Detailed Explanation

Python uses the C3 linearization algorithm to determine the MRO. You can view the MRO of a class using ClassName.__mro__ or ClassName.mro(). This is crucial for understanding multiple inheritance.

Code Example

print(D.mro())
# [D, B, C, A, object]
