ArrayList vs LinkedList?

Quick Answer

ArrayList corresponds to a dynamic array (fast random access O(1), slow insertion/deletion O(n)). LinkedList is a doubly linked list (fast insertion/deletion O(1), slow access O(n)).

Detailed Explanation

Use ArrayList when you read often but modify rarely. LinkedList is better if you constantly modify the list at the beginning or middle, but it has higher memory overhead per element.

How does HashMap work internally in Java?

Quick Answer

HashMap uses an array of buckets (Node<K,V>[]). It uses hashCode() to determine the bucket index and equals() to resolve collision via linked lists or Red-Black trees.

Detailed Explanation

When put(K, V) is called, the key's hash is calculated to find the index. If the bucket is empty, the node is added. If not (collision), it traverses the linked list. In Java 8, if the list size exceeds 8, it converts to a Balanced Tree (O(log n)) for performance.

Code Example

// Key Concept
int index = key.hashCode() & (n - 1);

How does a HashMap work internally?

Quick Answer

It uses hashing to store keys in buckets.

Detailed Explanation

HashMap stores key-value pairs in an array of buckets. It uses the hashCode() of the key to determine the index. If multiple keys hash to the same index (collision), they are stored in a linked list (or Red-Black tree in Java 8+) at that index. retrieval checks equals().

Code Example

How does method overriding work in Java and why is it useful?

Quick Answer

A subclass replaces a method inherited from its parent, allowing specialized behavior.

Detailed Explanation

Method overriding happens when a subclass defines a method with the same signature as a method in its superclass. Java uses dynamic dispatch, meaning the version of the method that runs depends on the actual object type at runtime, not the reference type. This lets subclasses provide more specific behavior while keeping a shared interface. It's the backbone of polymorphism.

Code Example
class Animal {
    void speak() { System.out.println("Some sound"); }
}

    @Override
    void speak() { System.out.println("Bark"); }
}

Animal a = new Dog();
a.speak(); // Bark

Why do Java collections use generics, and what problem do they solve?

Quick Answer

Generics enforce type safety at compile time and prevent ClassCastException.

Detailed Explanation

Before generics, Java collections stored raw Object references, forcing developers to cast values manually. This allowed runtime type errors that were hard to trace. Generics let collections specify the type of elements they hold, which the compiler checks. This improves safety, readability, and eliminates unnecessary casts.

Code Example
List<String> names = new ArrayList<>();
names.add("Alice");
String x = names.get(0); // no cast needed
