Are Java strings mutable?

Quick Answer

No, Java strings are immutable.

Detailed Explanation

Java String objects are immutable: once created their contents cannot be changed and operations that appear to modify a string produce new String instances. This immutability enables safe sharing (string pooling) and thread-safety but makes repeated concatenation inefficient; use StringBuilder or StringBuffer for many mutations. Pitfall: using == compares references, not content — use equals() to compare string values.

Code Example
String s = "Hi";
s = s + "!"; // creates a new String

ArrayList vs LinkedList?

Quick Answer

Dynamic array vs Doubly linked list.

Detailed Explanation

ArrayList is backed by a resizable array: it provides O(1) indexed access and compact memory layout but shifting elements makes mid-list inserts/removals O(n). LinkedList is a doubly linked list offering cheap insert/remove at known positions (O(1) if you have the node) but O(n) indexed access due to traversal. In most cases ArrayList is the better default due to better cache locality and lower per-element overhead.

Code Example
List<String> list = new ArrayList<>();

Quick Answer

== compares references; .equals() compares content.

Detailed Explanation

== checks whether two reference variables point to the identical object in memory, while .equals() is intended to test logical equality and can be overridden to compare object state. Quick Answer

Runnable doesn't return a result or throw checked exceptions. Callable returns a result and can throw exceptions.

Detailed Explanation

Runnable is a functional interface whose run method returns void and cannot throw checked exceptions, while Callable returns a result and can throw checked exceptions. Explain try, catch, and finally.

Quick Answer

Blocks used for exception handling.

Detailed Explanation

try wraps code that may throw exceptions, catch blocks handle specific exceptions that occur in the try block, and finally contains cleanup code that executes whether or not an exception was thrown. Use finally to release resources like streams or connections. Pitfall: returning from or calling System.exit in finally can suppress exceptions or alter control flow, so avoid returning from finally.

Code Example
try {
    int x = 1 / 0;
} catch (ArithmeticException e) {
    System.out.println("Error");
} finally {
    System.out.println("Done");
}

Explain the try-catch-finally block.

Quick Answer

try contains code that might throw an exception, catch handles the exception, and finally executes code regardless of the outcome (often for cleanup).

Detailed Explanation

try contains code that may throw exceptions, catch blocks handle specific exceptions, and finally contains cleanup code that runs regardless of whether an exception was thrown. Prefer try-with-resources for deterministic resource management when working with Closeable resources.

Code Example
try {
    openFile();
} catch (IOException e) {
    handleError(e);
} finally {
    closeFile();
}

Intermediate vs Terminal Operations?

Quick Answer

Intermediate operations (filter, map) are lazy and return a Stream. Terminal operations (collect, forEach) trigger processing and return a result.

Detailed Explanation

Intermediate operations (like filter, map, sorted) return another Stream and are lazy, building up a pipeline without executing until a terminal operation is invoked. Terminal operations (like collect, forEach, reduce) trigger evaluation of the pipeline and produce a result or side effects. Pitfalls: forgetting a terminal operation means nothing runs, and some intermediate ops are stateful (sorted, distinct) and can increase memory or change parallel behavior.

Code Example
stream.filter(...); // Nothing happens until .collect()

Life Cycle of a Thread?

Quick Answer

New, Runnable, Blocked, Waiting, Timed_Waiting, Terminated.

Detailed Explanation

A thread goes through states: NEW (created), RUNNABLE (start called and eligible to run), BLOCKED/WAITING/TIMED_WAITING (waiting for locks, IO, or timed waits), and TERMINATED (finished execution). Transitions occur via start, synchronization/wait/park, sleep/join/await, interrupt, and normal or exceptional return from run. Pitfalls: RUNNABLE means runnable by the scheduler (not necessarily running), and relying on thread scheduling for correctness is fragile.

Detailed Explanation

What is a Deadlock?

Quick Answer

A situation where two or more threads are blocked forever, waiting for each other.

Detailed Explanation

A deadlock is a situation where two or more threads are blocked forever because each holds a lock the other needs, forming a circular wait. Preventive strategies include consistent lock ordering, using tryLock with timeouts, reducing lock scope, or avoiding nested locks. Pitfalls: deadlocks can be intermittent and environment-dependent, so reproduce by thread dumps or logs and design to eliminate circular dependencies.

What is the difference between an Interface and an Abstract Class?

Quick Answer

An Abstract Class can have state (fields) and constructors, while an Interface (prior to Java 8) is purely a contract of methods. A class can implement multiple interfaces but extend only one abstract class.

Detailed Explanation

Abstract classes can provide state (fields), constructors, and shared implementation; interfaces define a behavioral contract and (since Java 8) may include default and static methods. Use abstract classes when you need to share implementation or state; use interfaces for composable capabilities. A class can implement multiple interfaces but extend only one class.

Code Example
interface Flyable { void fly(); }
abstract class Bird { int wings; }

What is the difference between break and continue?

Quick Answer

break exits the loop; continue skips the current iteration.

Detailed Explanation

break immediately exits the nearest loop (or a labeled loop if specified), while continue skips the remainder of the current iteration and proceeds to the next iteration. Use continue to ignore specific cases without breaking the loop entirely.

Code Example
if (i == 5) break;

What is the difference between Overloading and Overriding?

Quick Answer

Overloading is same name different params; Overriding is same signature in child class.

Detailed Explanation

Overloading occurs when methods share the same name but have different parameter lists (compile-time polymorphism). Overriding occurs when a subclass provides a specific implementation for a method declared in its superclass (runtime polymorphism). Overriding respects access and return-type rules and can use @Override for clarity.

Code Example
// Overloading
add(int a)
add(int a, int b)

What is the Enhanced for loop (for-each)?

Quick Answer

A simplified loop for iterating over arrays or collections.

Detailed Explanation

The enhanced for-loop (for (T item : collection)) simplifies iterating over arrays and Iterable collections by handling the iterator internals for you. It is concise and less error-prone for simple iteration but cannot remove elements during traversal (use an explicit iterator for safe removal).

Code Example
for (String s : list) { ... }

What is the finally block?

Quick Answer

A block that executes regardless of exception occurrence.

Detailed Explanation

A finally block contains cleanup code that runs after the try/catch sequence, regardless of whether an exception was thrown or a return occurred. It is commonly used to release resources such as streams or connections. Since Java 7, prefer try-with-resources for deterministic resource management; finally remains useful when try-with-resources is not applicable.

Code Example
try { ... } finally { scanner.close(); }

What is the Java Stream API?

Quick Answer

A functional-style API introduced in Java 8 for processing sequences of elements.

Detailed Explanation

The Java Stream API provides a high-level, declarative way to process collections of data using pipeline operations like map, filter, and reduce. Streams support lazy evaluation and can be executed sequentially or in parallel to express transformations without mutating the source. Pitfalls: streams are single-use, not a data structure, and side effects inside stream operations are error-prone and discouraged.

Code Example
List<String> names = list.stream()
    .filter(s -> s.startsWith("A"))
    .collect(Collectors.toList());

What is the purpose of a for loop in Java?

Quick Answer

To repeat a block of code a specific number of times.

Detailed Explanation

A for loop repeats a block of code using an initialization, a loop condition, and an update expression, which makes it convenient for iterating a known number of times. The loop executes while the condition is true and stops when it becomes false. Pitfall: off-by-one errors in the condition or an incorrect update expression can cause missed iterations or infinite loops.

Code Example
for (int i = 0; i < 5; i++) {
    System.out.println(i);
}

What is the purpose of the super keyword?

Quick Answer

super is a reference variable used to refer to the immediate parent class object.

Detailed Explanation

super refers to the immediate superclass and is used to call the parent constructor (super(...)) and to access superclass methods or fields hidden by the subclass. It helps reuse parent behavior and resolve naming conflicts.

Code Example
class Child extends Parent {
    Child() {
        super(); // Calls Parent constructor
    }
}

What is the purpose of the this keyword?

Quick Answer

Refers to the current object instance.

Detailed Explanation

this refers to the current instance of a class and is used to access instance variables, invoke other constructors (this(...)), or pass the current object to other methods. It is commonly used to disambiguate fields from method parameters with the same name.

What is the ternary operator?

Quick Answer

Conditional operator ? :.

Detailed Explanation

The ternary operator condition ? expr1 : expr2 is a compact form of if-else that returns expr1 if the condition is true, otherwise expr2. It's handy for simple conditional expressions but avoid over-nesting to keep code readable.

Why is String immutable?

Quick Answer

For security, caching, and thread safety.

Detailed Explanation

Strings are immutable: once created their character content cannot be changed. Immutability enables safe sharing via the String pool (reusing literals), allows caching of hash codes for efficient hashmap keys, and provides thread-safety without synchronization. If you need mutable sequences, use StringBuilder or StringBuffer instead.

Code Example
String s = "Hello";
s.concat(" World"); // s is still "Hello"

Why is the main method static?

Quick Answer

So the JVM can call it without creating an object.

Detailed Explanation

The main method is static so the JVM can invoke it without instantiating the class. It serves as the program's entry point; since no objects exist before startup, the method needs to be callable on the class itself.

Code Example
public static void main(String[] args)

Wrapper Classes vs Primitives?

Quick Answer

Objects (Integer) vs raw values (int).

Detailed Explanation

Primitives (int, boolean, etc.) store raw values and are lightweight and fast. Wrapper classes (Integer, Boolean, etc.) are objects that box primitive values: they can be null, provide utility methods, and are required for use in generic types like List<Integer>. Autoboxing/unboxing converts between primitives and wrappers automatically but can introduce performance overhead and unexpected NullPointerExceptions when a wrapper is null.

Code Example
int x = 5;
Integer y = 5; // Auto-boxing
