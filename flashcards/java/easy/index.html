Are Java strings mutable?

Quick Answer

No, Java strings are immutable.

Detailed Explanation

Java String objects are immutable, meaning their character sequence cannot be changed after creation, with any operation that appears to modify a string actually creating a new String instance. Core functionality includes thread-safe sharing, string interning for memory efficiency, and extensive utility methods like substring(), concat(), and replace(). Key features encompass the string pool (a JVM cache of literal strings) and methods for comparison, searching, and manipulation. Internal architecture uses a char array with an offset and length for efficient substring operations without copying. Recommended practices include using StringBuilder or StringBuffer for multiple concatenations, preferring equals() over == for content comparison, and using string literals for constants. Common mistakes include using == for comparison (compares references, not content), inefficient concatenation in loops, and forgetting that substring() shares the underlying char array in older Java versions. Practical use cases include text processing, configuration keys, and immutable identifiers. Performance implications: immutability enables safe sharing but concatenation creates many temporary objects; StringBuilder is mutable and efficient for building strings incrementally.

Code Example
import java.util.Arrays;

public class StringImmutabilityDemo {
    public static void main(String[] args) {
        // String literals are interned (shared)
        String s1 = "Hello";
        String s2 = "Hello";
        System.out.println("s1 == s2: " + (s1 == s2)); // true (same reference)
        System.out.println("s1.equals(s2): " + s1.equals(s2)); // true (same content)
        
        // Creating new strings
        String s3 = new String("Hello"); // Not interned
        System.out.println("s1 == s3: " + (s1 == s3)); // false (different references)
        
        // Immutability demonstration
        String original = "Hello";
        String modified = original.concat(" World"); // Creates new string
        System.out.println("Original: " + original); // Still "Hello"
        System.out.println("Modified: " + modified); // "Hello World"
        
        // Inefficient concatenation (creates multiple objects)
        String result = "";
        for (int i = 0; i < 5; i++) {
            result += i + " "; // Creates new string each time
        }
        System.out.println("Inefficient result: " + result);
        
        // Efficient concatenation using StringBuilder
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < 5; i++) {
            sb.append(i).append(" "); // Modifies same object
        }
        String efficientResult = sb.toString();
        System.out.println("Efficient result: " + efficientResult);
        
        // String methods with error handling
        String text = "  Hello World  ";
        try {
            String trimmed = text.trim(); // Remove whitespace
            String upper = trimmed.toUpperCase(); // Convert to uppercase
            String substring = upper.substring(0, 5); // Extract first 5 chars
            System.out.println("Processed: '" + substring + "'");
            
            // Safe substring with bounds checking
            int startIndex = 6;
            int length = 5;
            if (startIndex >= 0 && startIndex + length <= upper.length()) {
                String safeSubstring = upper.substring(startIndex, startIndex + length);
                System.out.println("Safe substring: '" + safeSubstring + "'");
            } else {
                System.out.println("Invalid substring indices");
            }
            
        } catch (StringIndexOutOfBoundsException e) {
            System.out.println("String operation error: " + e.getMessage());
        }
        
        // String comparison examples
        String str1 = "apple";
        String str2 = "Apple";
        System.out.println("Case-sensitive equals: " + str1.equals(str2)); // false
        System.out.println("Case-insensitive equals: " + str1.equalsIgnoreCase(str2)); // true
        
        // Splitting strings
        String csv = "name,age,city";
        String[] parts = csv.split(",");
        System.out.println("Split result: " + Arrays.toString(parts));
    }
}

ArrayList vs LinkedList?

Quick Answer

Dynamic array vs Doubly linked list.

Detailed Explanation

ArrayList is a resizable array implementation providing fast random access, while LinkedList is a doubly-linked list offering efficient insertions/deletions at any position. Core functionality and key features: ArrayList excels at indexed access and iteration; LinkedList shines at frequent modifications. Internal mechanics and architecture: ArrayList uses a backing array that grows dynamically; LinkedList maintains node references for bidirectional traversal. Recommended practices and patterns: Default to ArrayList for most use cases; choose LinkedList only when frequent insertions/deletions dominate and random access is rare. Common mistakes and how to avoid them: Using LinkedList for indexed access (O(n) vs ArrayList's O(1)); not considering memory overhead of LinkedList nodes. Practical use cases and scenarios: ArrayList for databases result sets, configuration lists; LinkedList for queue implementations, frequent modifications. Performance and cost implications: ArrayList has better cache locality and lower memory per element; LinkedList has higher memory overhead but better modification performance for large lists.

Code Example
import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;
import java.util.Iterator;

public class ListComparison {
    public static void main(String[] args) {
        // ArrayList: Fast random access, good for iteration
        List<String> arrayList = new ArrayList<>();
        arrayList.add("First");
        arrayList.add("Second");
        arrayList.add("Third");
        
        // O(1) indexed access - ArrayList strength
        System.out.println("ArrayList get(1): " + arrayList.get(1)); // Instant
        
        // Efficient iteration
        for (String item : arrayList) {
            System.out.println("ArrayList item: " + item);
        }
        
        // LinkedList: Fast insertions/deletions, good for modifications
        List<String> linkedList = new LinkedList<>();
        linkedList.add("First");
        linkedList.add("Second");
        linkedList.add("Third");
        
        // O(n) indexed access - LinkedList weakness
        System.out.println("LinkedList get(1): " + linkedList.get(1)); // Traverses nodes
        
        // Efficient insertion at beginning
        linkedList.addFirst("Zero"); // O(1)
        linkedList.addLast("Fourth"); // O(1)
        
        // Demonstrate performance difference
        int operations = 10000;
        
        // ArrayList: Fast random access
        long start = System.nanoTime();
        for (int i = 0; i < operations; i++) {
            arrayList.get(arrayList.size() / 2);
        }
        long arrayTime = System.nanoTime() - start;
        
        // LinkedList: Slow random access
        start = System.nanoTime();
        for (int i = 0; i < operations; i++) {
            linkedList.get(linkedList.size() / 2);
        }
        long linkedTime = System.nanoTime() - start;
        
        System.out.println("ArrayList random access time: " + arrayTime / 1000000 + "ms");
        System.out.println("LinkedList random access time: " + linkedTime / 1000000 + "ms");
        
        // Memory usage comparison
        System.out.println("ArrayList size: " + arrayList.size());
        System.out.println("LinkedList size: " + linkedList.size());
        
        // Iterator usage (both support efficiently)
        Iterator<String> iterator = linkedList.iterator();
        while (iterator.hasNext()) {
            String item = iterator.next();
            if (item.equals("Second")) {
                iterator.remove(); // Safe removal during iteration
            }
        }
    }
}

Difference between == and .equals()?

Quick Answer

== compares references; .equals() compares content.

Detailed Explanation

The == operator checks reference equality (whether two variables point to the same object in memory), while .equals() method tests logical equality (whether objects represent the same value). Core functionality includes == being a language operator for identity comparison and .equals() being overridable for value-based comparison. Internal mechanics show == comparing memory addresses directly, while .equals() calls the object's implementation, defaulting to reference equality unless overridden. Recommended practices include using == for primitives and enum constants, .equals() for objects, and implementing both equals() and hashCode() together. Common mistakes include using == for string comparison (use .equals()), forgetting null checks before .equals(), or overriding equals() without hashCode(). Practical use cases include string comparison, collection lookups, and custom value objects. Performance implications show == being faster (direct comparison) while .equals() may involve method calls and field comparisons, potentially slower for complex objects.

Code Example
import java.util.*;

public class EqualityExample {
    
    static class Person {
        private String name;
        private int age;
        
        public Person(String name, int age) {
            this.name = name;
            this.age = age;
        }
        
        // Proper equals implementation
        @Override
        public boolean equals(Object obj) {
            if (this == obj) return true; // Reference equality first
            if (!(obj instanceof Person)) return false;
            Person other = (Person) obj;
            return age == other.age && Objects.equals(name, other.name);
        }
        
        // Must override hashCode when overriding equals
        @Override
        public int hashCode() {
            return Objects.hash(name, age);
        }
        
        @Override
        public String toString() {
            return "Person{name='" + name + "', age=" + age + "}";
        }
    }
    
    public static void stringComparison() {
        String s1 = "hello";
        String s2 = "hello";
        String s3 = new String("hello");
        
        System.out.println("s1 == s2: " + (s1 == s2)); // true (string pool)
        System.out.println("s1.equals(s2): " + s1.equals(s2)); // true
        System.out.println("s1 == s3: " + (s1 == s3)); // false (different objects)
        System.out.println("s1.equals(s3): " + s1.equals(s3)); // true (same content)
    }
    
    public static void primitiveComparison() {
        int a = 5;
        int b = 5;
        Integer c = 5; // Autoboxed
        Integer d = 5;
        Integer e = 500; // Beyond cache range
        Integer f = 500;
        
        System.out.println("a == b: " + (a == b)); // true (primitive equality)
        System.out.println("c == d: " + (c == d)); // true (Integer cache)
        System.out.println("e == f: " + (e == f)); // false (no cache)
        System.out.println("c.equals(d): " + c.equals(d)); // true
        System.out.println("e.equals(f): " + e.equals(f)); // true
    }
    
    public static void objectComparison() {
        Person p1 = new Person("Alice", 30);
        Person p2 = new Person("Alice", 30);
        Person p3 = p1; // Same reference
        
        System.out.println("p1 == p2: " + (p1 == p2)); // false (different objects)
        System.out.println("p1.equals(p2): " + p1.equals(p2)); // true (same values)
        System.out.println("p1 == p3: " + (p1 == p3)); // true (same reference)
        System.out.println("p1.equals(p3): " + p1.equals(p3)); // true
    }
    
    public static void collectionUsage() {
        Set<Person> personSet = new HashSet<>();
        Person p1 = new Person("Bob", 25);
        Person p2 = new Person("Bob", 25);
        
        personSet.add(p1);
        System.out.println("Set contains p2: " + personSet.contains(p2)); // true (uses equals)
        
        Map<Person, String> personMap = new HashMap<>();
        personMap.put(p1, "Developer");
        System.out.println("Map get p2: " + personMap.get(p2)); // Developer (uses equals and hashCode)
    }
    
    public static void nullSafety() {
        String s1 = "hello";
        String s2 = null;
        
        // Safe null check
        System.out.println("s1 equals s2 (safe): " + Objects.equals(s1, s2)); // false
        
        // Dangerous - can throw NullPointerException
        try {
            // System.out.println(s2.equals(s1)); // NPE!
        } catch (NullPointerException e) {
            System.out.println("NPE caught: " + e.getMessage());
        }
    }
    
    public static void main(String[] args) {
        System.out.println("=== String Comparison ===");
        stringComparison();
        
        System.out.println("\n=== Primitive Comparison ===");
        primitiveComparison();
        
        System.out.println("\n=== Object Comparison ===");
        objectComparison();
        
        System.out.println("\n=== Collection Usage ===");
        collectionUsage();
        
        System.out.println("\n=== Null Safety ===");
        nullSafety();
    }
}

Explain try, catch, and finally.

Quick Answer

Blocks used for exception handling.

Detailed Explanation

The try-catch-finally construct provides structured exception handling where try encloses code that might throw exceptions, catch blocks handle specific exception types, and finally ensures cleanup code executes regardless of outcome. Core functionality includes separating error handling from business logic and guaranteeing resource cleanup. Internal mechanics involve the JVM unwinding the stack when exceptions occur, matching catch blocks by type hierarchy, and always executing finally before control transfer. Recommended practices include catching specific exceptions, using try-with-resources for automatic cleanup, and avoiding empty catch blocks. Common mistakes include catching Exception broadly (hiding bugs), swallowing exceptions silently, or returning from finally (suppressing exceptions). Practical use cases include file I/O, network operations, database transactions, and any operation with potential failure points. Performance implications include try-catch having minimal overhead in success paths but significant cost during exception throwing due to stack trace creation and unwinding.

Code Example
import java.io.*;
import java.nio.file.*;
import java.util.Scanner;

public class ExceptionHandlingExample {
    
    // Basic try-catch-finally
    public static void basicExample() {
        Scanner scanner = null;
        try {
            scanner = new Scanner(System.in);
            System.out.print("Enter a number: ");
            int number = scanner.nextInt();
            System.out.println("You entered: " + number);
        } catch (Exception e) {
            System.err.println("Error reading input: " + e.getMessage());
        } finally {
            // Cleanup code - always executes
            if (scanner != null) {
                scanner.close();
                System.out.println("Scanner closed in finally");
            }
        }
    }
    
    // Multiple catch blocks
    public static void multipleCatchExample() {
        try {
            String text = null;
            System.out.println(text.length()); // NullPointerException
            int result = 10 / 0; // ArithmeticException
        } catch (NullPointerException e) {
            System.err.println("Null pointer: " + e.getMessage());
        } catch (ArithmeticException e) {
            System.err.println("Arithmetic error: " + e.getMessage());
        } catch (Exception e) {
            System.err.println("General exception: " + e.getMessage());
        } finally {
            System.out.println("Finally block executed");
        }
    }
    
    // Try-with-resources (automatic resource management)
    public static void tryWithResourcesExample() {
        // Resources are automatically closed
        try (BufferedReader reader = Files.newBufferedReader(Paths.get("example.txt"));
             BufferedWriter writer = Files.newBufferedWriter(Paths.get("output.txt"))) {
            
            String line;
            while ((line = reader.readLine()) != null) {
                writer.write(line.toUpperCase());
                writer.newLine();
            }
            
        } catch (IOException e) {
            System.err.println("File operation failed: " + e.getMessage());
        }
        // No need for finally - resources closed automatically
    }
    
    // Nested try-catch
    public static void nestedExample() {
        try {
            System.out.println("Outer try");
            try {
                int result = 10 / 0;
            } catch (ArithmeticException e) {
                System.err.println("Inner catch: " + e.getMessage());
                throw new RuntimeException("Wrapped exception", e); // Re-throwing
            }
        } catch (RuntimeException e) {
            System.err.println("Outer catch: " + e.getMessage());
            // e.getCause() contains the original exception
        } finally {
            System.out.println("Outer finally");
        }
    }
    
    // Custom exception example
    public static void validateAge(int age) throws InvalidAgeException {
        if (age < 0 || age > 150) {
            throw new InvalidAgeException("Age must be between 0 and 150", age);
        }
    }
    
    // Custom exception class
    static class InvalidAgeException extends Exception {
        private final int invalidAge;
        
        public InvalidAgeException(String message, int invalidAge) {
            super(message);
            this.invalidAge = invalidAge;
        }
        
        public int getInvalidAge() {
            return invalidAge;
        }
    }
    
    public static void main(String[] args) {
        System.out.println("=== Basic Example ===");
        basicExample();
        
        System.out.println("\n=== Multiple Catch ===");
        multipleCatchExample();
        
        System.out.println("\n=== Try-with-Resources ===");
        tryWithResourcesExample();
        
        System.out.println("\n=== Nested Example ===");
        nestedExample();
        
        System.out.println("\n=== Custom Exception ===");
        try {
            validateAge(25); // Valid
            System.out.println("Age is valid");
            validateAge(-5); // Invalid
        } catch (InvalidAgeException e) {
            System.err.println("Validation failed: " + e.getMessage() + 
                            " (invalid age: " + e.getInvalidAge() + ")");
        }
    }
}

Explain the try-catch-finally block.

Quick Answer

try contains code that might throw an exception, catch handles the exception, and finally executes code regardless of the outcome (often for cleanup).

Detailed Explanation

The try block contains code that may throw exceptions. catch blocks handle specific exception types, with more specific types before general ones. finally executes cleanup code regardless of exceptions. Since Java 7, try-with-resources automatically closes resources. Exceptions are checked (compile-time) or unchecked (runtime). Internally, exceptions use stack unwinding. Recommended practices: Catch specific exceptions, use try-with-resources for AutoCloseable objects. Common mistakes include catching Exception broadly or forgetting resource cleanup. Practical use cases: File I/O, network operations. Performance implications: Exceptions are expensive due to stack traces; use for exceptional cases only.

Code Example
import java.io.*;

public class ExceptionExample {
    public static void main(String[] args) {
        // Traditional try-catch-finally
        FileReader fr = null;
        try {
            fr = new FileReader("example.txt");
            int data = fr.read();
            System.out.println("Read: " + (char) data);
        } catch (FileNotFoundException e) {
            System.err.println("File not found: " + e.getMessage());
        } catch (IOException e) {
            System.err.println("IO error: " + e.getMessage());
        } finally {
            if (fr != null) {
                try {
                    fr.close(); // Manual cleanup
                } catch (IOException e) {
                    System.err.println("Error closing file: " + e.getMessage());
                }
            }
        }
        
        // Try-with-resources (Java 7+): automatic resource management
        try (BufferedReader br = new BufferedReader(new FileReader("example.txt"))) {
            String line = br.readLine();
            System.out.println("Line: " + line);
        } catch (FileNotFoundException e) {
            System.err.println("File not found: " + e.getMessage());
        } catch (IOException e) {
            System.err.println("IO error: " + e.getMessage());
        } // No finally needed - resources auto-closed
        
        // Multiple catch blocks
        try {
            int result = divide(10, 0);
        } catch (ArithmeticException e) {
            System.err.println("Arithmetic error: " + e.getMessage());
        } catch (Exception e) {
            System.err.println("General error: " + e.getMessage());
        }
    }
    
    private static int divide(int a, int b) throws ArithmeticException {
        if (b == 0) {
            throw new ArithmeticException("Division by zero");
        }
        return a / b;
    }
}

How do you declare an array in Java?

Quick Answer

Use the syntax: type[] arrayName = new type[size];

Detailed Explanation

An array in Java is a fixed-size, homogeneous container for storing multiple values of the same type, with elements accessed via zero-based integer indices. Core functionality includes declaration, initialization, and manipulation of contiguous memory blocks. Key features encompass length property for bounds checking, support for primitives and objects, and the ability to create multidimensional arrays. Internal architecture allocates memory on the heap with a reference to the array object containing length and element data. Recommended practices include using enhanced for-loops for iteration, checking bounds before access, and preferring collections like ArrayList for dynamic sizing. Common mistakes include off-by-one errors in indexing, accessing negative indices or indices >= length (causing ArrayIndexOutOfBoundsException), and confusing array declaration syntax. Practical use cases include storing collections of primitives for performance, implementing data structures like stacks/queues, and representing matrices in multidimensional arrays. Performance implications: arrays provide O(1) access time but fixed size requires copying for resizing; primitives arrays are memory-efficient while object arrays store references.

Code Example
import java.util.Arrays;

public class ArrayDemo {
    public static void main(String[] args) {
        // Declaration and initialization styles
        
        // 1. Declare and allocate separately
        int[] numbers1;
        numbers1 = new int[5]; // Default values: 0 for int
        
        // 2. Declare and allocate together
        String[] names = new String[3]; // Default values: null for objects
        
        // 3. Declare, allocate, and initialize
        double[] prices = {10.5, 20.0, 15.75}; // Array literal
        
        // 4. Anonymous array
        int[] anonymous = new int[]{1, 2, 3, 4, 5};
        
        // Accessing elements with bounds checking
        try {
            for (int i = 0; i < numbers1.length; i++) {
                numbers1[i] = i * 10; // Safe access
                System.out.println("numbers1[" + i + "] = " + numbers1[i]);
            }
            
            // This would throw ArrayIndexOutOfBoundsException
            // numbers1[5] = 50; // Index 5 is out of bounds for length 5
            
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Array access error: " + e.getMessage());
        }
        
        // Enhanced for-loop (for-each) - safer iteration
        System.out.println("Prices using enhanced for-loop:");
        for (double price : prices) {
            System.out.println(price);
        }
        
        // Multidimensional arrays
        int[][] matrix = new int[3][4]; // 3 rows, 4 columns
        
        // Initialize matrix
        for (int i = 0; i < matrix.length; i++) {
            for (int j = 0; j < matrix[i].length; j++) {
                matrix[i][j] = i * j;
            }
        }

        System.out.println("Matrix:");
        for (int[] row : matrix) {

How does a do-while loop differ from a while loop?

Quick Answer

It executes the block at least once.

Detailed Explanation

A do-while loop executes its body at least once before evaluating the exit condition, unlike a while loop that checks the condition first and may not execute at all. Core functionality ensures guaranteed execution for initialization or user interaction scenarios. Internally, it uses a post-test loop structure with the condition checked after each iteration. Recommended practices include using do-while for menu-driven programs and input validation requiring at least one attempt. Common mistakes involve forgetting the semicolon after the while condition or creating infinite loops due to condition errors. Practical use cases include user menus, game loops, and reading input until valid data is provided. Performance implications are similar to while loops, with the guarantee of one execution being the key difference.

Code Example
import java.util.Scanner;

public class DoWhileExample {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        
        // Menu-driven program: executes at least once
        int choice;
        do {
            System.out.println("Menu:");
            System.out.println("1. Option 1");
            System.out.println("2. Option 2");
            System.out.println("0. Exit");
            System.out.print("Choose: ");
            
            try {
                choice = scanner.nextInt();
                switch (choice) {
                    case 1:
                        System.out.println("Executing option 1");
                        break;
                    case 2:
                        System.out.println("Executing option 2");
                        break;
                    case 0:
                        System.out.println("Exiting...");
                        break;
                    default:
                        System.out.println("Invalid choice");
                }
            } catch (Exception e) {
                System.out.println("Invalid input, please enter a number");
                scanner.nextLine();  // Clear invalid input
                choice = -1;  // Continue loop
            }
        } while (choice != 0);
        
        // Input validation: try at least once
        String input;
        do {
            System.out.print("Enter 'yes' or 'no': ");
            input = scanner.next().toLowerCase();
        } while (!input.equals("yes") && !input.equals("no"));
        
        System.out.println("You entered: " + input);
        
        // Comparison with while loop
        System.out.println("\nComparison:");
        int counter = 5;
        
        System.out.println("While loop:");
        while (counter < 5) {  // Condition false, never executes
            System.out.println("This won't print");
        }
        
        System.out.println("Do-while loop:");
        do {
            System.out.println("This executes once: " + counter);
        } while (counter < 5);  // Condition checked after
        
        scanner.close();
    }
}

What causes a NullPointerException?

Accessing a member of a null reference.

Detailed Explanation

NullPointerException occurs when attempting to dereference a null reference by accessing fields, calling methods, or using array operations on null. Core functionality protects against invalid memory access at runtime. Internally, the JVM checks for null before dereferencing and throws the exception. Recommended practices include null checks, Optional usage, and defensive programming. Common mistakes include assuming references aren't null without verification or improper exception handling. Practical use cases include uninitialized fields, failed object creation, and API return values. Performance implications include the overhead of null checks, but catching NPEs early prevents larger issues.

It means the member belongs to the class, not instances.

Core functionality includes providing shared state and utility methods that don't require object context. Internal mechanics involve static members being stored in the method area of the JVM heap, with static initialization blocks executing in declaration order during class loading. Recommended practices include using static methods for pure functions, static constants for configuration, and static factory methods for object creation patterns. Common mistakes include accessing instance members from static methods (causing compile errors), using static fields for mutable shared state (leading to thread-safety issues), or over-relying on static methods which can make code hard to test and extend. Practical use cases include utility classes (Math, Collections), singleton patterns, factory methods, and constants. Performance implications include faster access since no object dereference is needed, but static initialization can impact class loading time, and excessive static state can increase memory footprint and complicate testing.

What does the switch statement do in Java?

Quick Answer

It selects and executes a block of code based on a matching value.

Detailed Explanation

The switch statement evaluates an expression and transfers control to the matching case label, executing statements sequentially from that point. Core functionality includes supporting primitive types (int, char, byte, short), their wrappers, String (since Java 7), and enum types, with each case representing a constant value to match against. Key features include fall-through behavior where execution continues to subsequent cases unless stopped by break, and a default case for unmatched values. Internal mechanics involve a jump table for efficient constant-time lookup with primitives, while String switches use hash-based comparison. Modern Java (14+) introduced switch expressions that return values and use arrow syntax (->) to eliminate fall-through, improving readability and reducing bugs. Recommended practices include using break consistently, preferring switch expressions for value-returning switches, and using enums for type-safe switches. Common mistakes include missing break statements causing unintended fall-through, and using switches for complex conditions better suited to if-else chains. Practical use cases include menu selections, state machines, and parsing command-line arguments. Performance implications: traditional switches are fast for primitives but String switches involve method calls; switch expressions can be more concise but compile to similar bytecode.

Code Example
import java.util.Scanner;

public class SwitchDemo {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        
        // Traditional switch statement with fall-through
        System.out.print("Enter a number (1-3): ");
        int choice = scanner.nextInt();
        
        switch (choice) {
            case 1:
                System.out.println("You chose option 1");
                // Fall-through to case 2 (intentional)
            case 2:
                System.out.println("Processing option 2");
                break; // Stop fall-through
            case 3:
                System.out.println("You chose option 3");
                break;
            default:
                System.out.println("Invalid choice");
                break;
        }
        
        // Modern switch expression (Java 14+)
        String dayType = switch (choice) {
            case 1 -> "Weekday"; // Arrow syntax, no fall-through
            case 2 -> "Weekend";
            case 3 -> "Holiday";
            default -> {
                System.out.println("Unknown day type");
                yield "Unknown"; // Yield value in block
            }
        };
        System.out.println("Day type: " + dayType);
        
        // String switch example
        System.out.print("Enter a color: ");
        String color = scanner.next().toLowerCase();
        
        switch (color) {
            case "red":
                System.out.println("#FF0000");
                break;
            case "green":
                System.out.println("#00FF00");
                break;
            case "blue":
                System.out.println("#0000FF");
                break;
            default:
                System.out.println("Unknown color");
        }
        
        // Enum switch (type-safe)
        enum Season { SPRING, SUMMER, FALL, WINTER }
        Season currentSeason = Season.SUMMER;
        
        switch (currentSeason) {
            case SPRING:
                System.out.println("Flowers bloom");
                break;
            case SUMMER:
                System.out.println("Hot weather");
                break;
            case FALL:
                System.out.println("Leaves change color");
                break;
            case WINTER:
                System.out.println("Snow falls");
                break;
        }
        
        scanner.close();
    }

What is the final keyword in Java?

Quick Answer

It indicates that the element cannot be changed.

Detailed Explanation

The final keyword in Java serves as a compile-time restriction that prevents reassignment or modification of variables, methods, and classes. Core functionality includes enforcing immutability at the reference level and protecting against accidental modifications. Internal mechanics involve the JVM treating final fields specially during optimization, potentially inlining values or enabling more aggressive compiler optimizations. Recommended practices include using final for constants (e.g., public static final int MAX_SIZE = 100;), method parameters in defensive programming, and local variables to prevent reassignment bugs. What is the difference between == and .equals()?

Quick Answer

== checks for reference equality (do variables point to the same memory address?), while .equals() checks for value equality (do objects contain the same data?).

Detailed Explanation

For primitive types, == compares values directly. For object references, == checks if both variables point to the same memory location (reference equality). The .equals() method, which can be overridden by classes, checks for logical equality based on content. For String, it compares character sequences. The contract requires that if two objects are equal via .equals(), they must have the same hashCode(). Internally, Object.equals() uses == by default. Recommended practices include overriding .equals() and hashCode() together for custom classes used in collections. Common mistakes include using == for strings or forgetting to override hashCode(), leading to issues in HashMap or HashSet. Practical use cases: Using .equals() for comparing user-defined objects; == for checking null or singleton instances. Performance implications: == is faster (O(1)) than .equals(), which may involve field comparisons (O(n)); improper overriding can cause infinite loops or incorrect behavior in hash-based collections.

What is the difference between int and Integer in Java?

Detailed Explanation

int is a primitive data type in Java that directly stores 32-bit signed integer values in memory, providing efficient arithmetic operations without any object overhead. Key features include utility methods like Integer.parseInt() for string conversion and Integer.valueOf() for caching commonly used values (flyweight pattern). Internally, Integer uses autoboxing/unboxing for automatic conversion between primitive and object forms, but this can introduce performance overhead due to object creation and potential NullPointerException when unboxing null values. Recommended practices include using primitives for performance-critical calculations and local variables, while using wrappers for collections and APIs requiring objects. Common mistakes include forgetting null checks before unboxing, leading to runtime exceptions, and using == for comparison instead of equals(). Practical use cases include mathematical computations with primitives for speed, and data structures like List<Integer> for dynamic collections. Performance implications: primitives are faster and use less memory (4 bytes vs 16+ bytes for objects), but wrappers enable nullability and polymorphism at the cost of boxing overhead in loops.

What is the finally block?

Wrapper Classes vs Primitives?

Quick Answer

Objects (Integer) vs raw values (int).

Detailed Explanation

Primitives (int, boolean, char, byte, short, long, float, double) are fundamental data types that store raw values directly in memory, while wrapper classes (Integer, Boolean, Character, etc.) are reference types that encapsulate primitive values as objects. Core functionality and key features: Primitives offer direct value storage with no object overhead, while wrappers provide object-oriented capabilities like nullability and method access. Internal mechanics and architecture: Primitives reside on the stack or in arrays, wrappers are heap-allocated objects with headers containing class information and synchronization data. Recommended practices and patterns: Use primitives for performance-critical code and simple calculations; use wrappers when null values are needed or for generic collections. Prefer wrapper.valueOf() over constructors for better memory efficiency. Common mistakes and how to avoid them: Unboxing null wrappers causes NullPointerException; always check for null before unboxing. Comparing wrappers with == instead of equals() leads to incorrect results due to reference comparison. Practical use cases and scenarios: Collections require wrappers (List); database operations often return wrappers; mathematical computations benefit from primitives. Performance and cost implications: Primitives are faster and use less memory (4 bytes vs 16+ bytes for Integer); autoboxing/unboxing adds overhead and can create many temporary objects in loops.

Code Example
import java.util.ArrayList;
import java.util.List;

public class WrapperDemo {
    public static void main(String[] args) {
        // Primitive usage - efficient for calculations
        int primitive = 42;
        System.out.println("Primitive value: " + primitive);
        
        // Autoboxing: primitive to wrapper
        Integer wrapper = primitive; // Compiler generates Integer.valueOf(42)
        System.out.println("Wrapper object: " + wrapper);
        
        // Unboxing: wrapper to primitive
        int backToPrimitive = wrapper; // Compiler generates wrapper.intValue()
        
        // Collections require wrappers
        List<Integer> numbers = new ArrayList<>();
        numbers.add(10); // Autoboxing
        numbers.add(20);
        
        // Safe unboxing with null check
        Integer nullable = getNullableInteger();
        if (nullable != null) {
            int safeValue = nullable; // Safe unboxing
            System.out.println("Safe value: " + safeValue);
        }
        
        // Common mistake: NullPointerException on unboxing
        Integer risky = null;
        try {
            int dangerous = risky; // Throws NPE
        } catch (NullPointerException e) {
            System.err.println("Avoided NPE by proper null checking");
        }
        
        // Correct comparison using equals()
        Integer a = 100;
        Integer b = 100;
        System.out.println("a == b: " + (a == b)); // May be false due to different objects
        System.out.println("a.equals(b): " + a.equals(b)); // Always true for same values
    }
    
    private static Integer getNullableInteger() {
        return Math.random() > 0.5 ? Integer.valueOf(99) : null;
    }
}
