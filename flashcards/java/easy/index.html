map vs flatMap in Streams?

Quick Answer

map transforms each element into one object. flatMap transforms each element into a Stream of objects and flattens them.

Detailed Explanation

Use map for 1-to-1 transformation (String -> Integer). Use flatMap for 1-to-Many (String -> List -> Stream).

Code Example

List flat = list.stream().flatMap(Collection::stream).collect(Collectors.toList());

Are Java strings mutable?

Quick Answer

No, Java strings are immutable.

Detailed Explanation

A Java String cannot be changed after it is created. Any operation that appears to modify a string actually creates a new one. This immutability improves security, performance (through string pools), and thread-safety. For mutable text, Java offers StringBuilder and StringBuffer.

Code Example
String s = "Hi";
s = s + "!"; // creates a new String

Explain try, catch, and finally.

Quick Answer

Blocks used for exception handling.

Detailed Explanation
  • try: Contains code that might throw an exception.
  • catch: Handles the exception if one occurs.
  • finally: Executes code regardless of whether an exception occurred (useful for cleanup).
Code Example
try {
    int x = 1 / 0;
} catch (ArithmeticException e) {
    System.out.println("Error");
} finally {
    System.out.println("Done");
}

Explain the try-catch-finally block.

Quick Answer

try contains code that might throw an exception, catch handles the exception, and finally executes code regardless of the outcome (often for cleanup).

Detailed Explanation

The finally block creates a guarantee that resources (like closing a file or DB connection) are released even if an exception occurs or a return statement is executed in the try block.

Code Example

try {
openFile();
} catch (IOException e) {
handleError(e);
} finally {
closeFile();
}

What is the difference between == and .equals()?

Quick Answer

== checks for reference equality (do variables point to the same memory address?), while .equals() checks for value equality (do objects contain the same data?).

Detailed Explanation

For primitives, == compares values. For objects, == strictly compares memory addresses. Most classes (like String, Integer) override equals() to compare the internal content.

Code Example

// s1 == s2 is false (different objects)
// s1.equals(s2) is true (same content)

What is the difference between int and Integer in Java?

Quick Answer

int is a primitive type, while Integer is its object wrapper.

Detailed Explanation

In Java, int is a primitive data type that directly stores a numeric value. Integer is a class that wraps an int value inside an object. What is the difference between String, StringBuilder, and StringBuffer?

Quick Answer

String is immutable. StringBuilder is mutable and not thread-safe (fastest). StringBuffer is mutable and thread-safe (synchronized).

Detailed Explanation

Because String is immutable, concatenating strings in a loop creates many temporary objects, stressing the GC. StringBuilder solves this by modifying the existing buffer. StringBuffer does the same but with synchronized methods for thread safety, which makes it slower than StringBuilder.

Code Example

String s = "Hello"; // Immutable
StringBuilder sb = new StringBuilder("Hello");
sb.append(" World"); // Efficient modification

What is the difference between an Interface and an Abstract Class?

Quick Answer

Interfaces define a contract; Abstract classes define a partial implementation.

Detailed Explanation
  • Interface: Can only have constants and method signatures (and default/static methods in Java 8+). A class can implement multiple interfaces.
  • Abstract Class: Can have instance variables and concrete methods. A class can extend only one abstract class.
Code Example

abstract class Bird { abstract void makeSound(); }

What is the difference between an Interface and an Abstract Class?

Quick Answer

An Abstract Class can have state (fields) and constructors, while an Interface (prior to Java 8) is purely a contract of methods. A class can implement multiple interfaces but extend only one abstract class.

Detailed Explanation

Abstract classes are used for 'is-a' relationships where code reuse is needed. Interfaces are used for 'can-do' capabilities (like Runnable, Serializable). Since Java 8, interfaces can have default and static methods.

Code Example

interface Flyable { void fly(); }
abstract class Bird { int wings; }
