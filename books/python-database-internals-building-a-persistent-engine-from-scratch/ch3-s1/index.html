The Virtual Machine (VM)

The Virtual Machine (VM) is a critical component of the database system, responsible for executing bytecode operations that manipulate the database state. In this section, we will delve into the implementation of the VM, focusing on its integration with the REPL and the execution of commands.

Introduction to the Virtual Machine

The VM is designed to work with the Table class, which manages row storage and retrieval. The VM executes bytecode operations generated from parsed SQL commands to manipulate the database state. The current implementation uses hardcoded commands to avoid complex SQL parsing, as per boundary constraints.

The execute_insert Method

The execute_insert method is a crucial part of the VM, responsible for inserting a new row into the table. This method must serialize a Row object using struct.pack and insert it into the Table using a Cursor for positioning. The serialization process involves packing the ID and username into a binary format, which is then stored in the table.

from typing import Final, Optional
import struct
from constants import PAGE_SIZE, PAGE_HEADER_FORMAT
from pager import Pager  # Reference shared_material CH2_class_Pager
from table import Table  # Reference shared_material CH2-S2_class_Table
from row import Row  # Reference shared_material CH1-S2_class_Row
from cursor import Cursor  # Reference existing knowledge from CH3

class VirtualMachine:
    def __init__(self, table: Table) -> None:
        self.table = table
        self.cursor = Cursor(table)
    
    def execute_insert(self, id_val: int, username: str) -> None:
        """Insert a new row into the table."""
        # Serialize the row manually using struct.pack for low-level control
        serialized_row = struct.pack('<I 32s', id_val, username.encode('utf-8'))
        
        # Position cursor at the start to find the next available slot
        self.cursor.cursor_start()
        
        # Write the serialized row data through the table using the cursor
        self.table.insert_row(self.cursor, serialized_row)

The execute_select Method

The execute_select method is another key component of the VM, responsible for retrieving and displaying all rows from the table. This method uses a Cursor to perform a linear scan with O(N) complexity, deserializing each Row using memoryview. The deserialization process involves unpacking the ID and username from the binary format, which is then returned as a list of Row objects.

    def execute_select(self) -> list[Row]:
        """Select all rows from the table."""
        rows = []
        self.cursor.cursor_start()
        
        while not self.cursor.cursor_end():
            # Access raw page data via table and cursor position
            page = self.table.pager.get_page(self.cursor.page_num)
            offset = self.cursor.row_index * Row.ROW_SIZE + PAGE_HEADER_FORMAT.size
            
            # Use memoryview for zero-copy slicing
            row_bytes = memoryview(page)[offset:offset + Row.ROW_SIZE]
            
            # Deserialize the row using struct.unpack
            id_val, username_bytes = struct.unpack('<I 32s', row_bytes)
            username = username_bytes.rstrip(b'\x00').decode('utf-8')
            
            # Construct and append Row object
            row = Row(id_val, username)
            rows.append(row)
            
            # Advance cursor to next row
            self.cursor.cursor_advance()
        
        return rows

Integration with REPL

The VM integrates with the REPL loop by receiving commands from user input, executing them via execute_insert or execute_select, and returning results for output. The REPL reads commands, evaluates them by calling VM methods, and prints results, forming a continuous interaction loop.

from repl import REPL  # Assume REPL class exists

def integrate_vm_with_repl(vm: VirtualMachine) -> None:
    """Example function showing VM integration into REPL loop."""
    repl = REPL()
    while True:
        command = repl.read_command()
        if command.startswith("insert"):
            # Parse hardcoded command, e.g., "insert 1 user1"
            parts = command.split()
            id_val = int(parts[1])
            username = parts[2]
            vm.execute_insert(id_val, username)
            repl.print_result("Inserted successfully")
        elif command == "select":
            rows = vm.execute_select()
            for row in rows:
                repl.print_result(f"ID: {row.id_val}, Username: {row.username}")
        else:
            repl.print_result("Unknown command")

Data Section: Up to 4088 bytes (PAGE_SIZE - header)
Row Slots: Fixed 36 bytes each, approximately 113 rows per page
Offset Calculation: Row address = page_num * PAGE_SIZE + header_size + row_index * ROW_SIZE

Architecture of Virtual Machine Integration

The architecture of the Virtual Machine integration can be visualized as follows:

Diagram Description: Architecture of Virtual Machine Integration

  • Flow: User Input → REPL (Read Command) → Virtual Machine (Execute Command: execute_insert or execute_select) → Table (Manage Rows) → Pager (Handle Pages) → Disk Storage
  • Components: REPL, VirtualMachine, Cursor, Table, Pager, Row
  • Data Path: Commands flow from REPL to VM; VM uses Cursor to iterate over Table; Table uses Pager for disk I/O; Rows are serialized/deserialized with binary data.
  • Design Choice Explanation: Modular layers ensure separation of concerns; VM acts as execution engine driving Cursors based on hardcoded commands for simplicity.
