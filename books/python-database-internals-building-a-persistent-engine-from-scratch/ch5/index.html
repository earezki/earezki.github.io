B-Tree Implementation: Internal Nodes and Splitting

The B-Tree data structure is a self-balancing tree that maintains sorted keys for efficient search, insertion, and deletion operations. In the previous sections, we covered the leaf node structure and operations. Now, we will delve into the implementation of internal nodes and the splitting algorithm, which are crucial for the tree’s growth and balance.

Internal Node Structure

Internal nodes in a B-Tree store keys and child pointers, which are used for routing searches and maintaining the tree structure. The internal node header contains metadata such as Node Type (1 byte), Is Root (1 byte), and Num Keys (4 bytes), formatted in little-endian byte order. Each cell in an internal node consists of a key (4 bytes) and a child pointer (4 bytes), with the keys sorted in ascending order and the child pointers positioned between them to guide searches down the tree.

The following markdown table illustrates the internal node format:

FieldSize (bytes)Description
Node Type1Byte indicating node type: 1 for internal.
Is Root1Boolean flag: 1 if root, 0 otherwise.
Num Keys4Unsigned integer count of keys in the internal node.
Key44-byte integer used for sorting and searching.
Child Pointer44-byte page number pointing to a child node.
Cell Size8Total size per cell: Key + Child Pointer.
Max Cells per Page~511Calculated as (PAGE_SIZE - HEADER_SIZE) // CELL_SIZE, with PAGE_SIZE=4096, HEADER_SIZE=6, CELL_SIZE=8.

Splitting Algorithm

When an internal node becomes full, it needs to be split to maintain the B-Tree properties. The splitting algorithm involves finding the median key, creating a new sibling node, redistributing keys and pointers, and updating the parent node or creating a new root if necessary. This process ensures that the tree remains balanced and that all leaf nodes are at the same depth.

### Parent-Child Relationship Tracking

To maintain the tree structure, it is essential to track the parent-child relationships between nodes. This can be achieved by storing parent pointers in node headers or using a stack during tree traversal to manage splits and inserts.
